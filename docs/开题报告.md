# 面向Web与微信小程序的个人学习资料智能整理系统设计与实现

# 一、选题依据及意义

随着学习资源逐步数字化，学生在课堂学习、课后自学和项目实践中接触的资料形式日益多样，包括电子课件、PDF文档、课堂截图以及碎片化文字笔记。这些资料通常分散在手机相册、聊天记录和电脑文件夹中，文件命名与分类方式缺乏统一，内容之间的联系也难以直观呈现。资料数量增加后，学生不仅需要找到原始文件，还需要理解其中的重点、整理概念并建立知识关联。依靠手工重命名、摘抄和分类能够完成基本管理，但重复操作较多，移动端采集与电脑端整理之间也容易出现信息断层。

文件管理、关键词检索和笔记分类能够改善资料存储与查找问题，但从文件保存到知识理解仍需要较多人工处理。大语言模型提供了摘要生成、内容分类与知识提炼的技术路径，OCR接口能够辅助识别图片中的文字。将这些能力直接接入系统时，还需要处理文档类型差异、长文档解析、模型输出偏差、跨资料关联和任务异常等问题。若系统只提供单次问答或独立的摘要按钮，资料处理过程仍较零散，生成结果与原文之间也可能缺乏可核查的联系。

本课题拟设计并实现面向Web与微信小程序的个人学习资料智能整理系统，并在系统中设置学习资料整理智能体，采用微信小程序与Web端配合的方式：小程序负责拍照上传与快速记录，Web端负责集中管理、深度解析和知识可视化。智能体根据资料类型和整理目标选择处理工具，组织文本提取、摘要生成、卡片整理和关联推荐，并保留结果来源与任务状态。研究的实践意义在于探索适合学生使用的资料整理流程，减少采集、归档和复习之间的重复操作；工程意义在于形成可验证的双端协同、异步任务与AI工具集成方案，为个人学习资料管理类应用提供实现参考。整理效率与结果质量是否改善，将通过后续测试评价。

# 二、研究目标与主要内容

## （一）研究目标

1. 建立统一的个人学习资料管理入口。支持图片、PDF和文字笔记的采集与归档，通过账户绑定和统一后端使小程序与Web端共享资料、标签及知识卡片，形成“移动采集—集中整理—双端查阅”的使用闭环。

2. 在系统中实现学习资料整理智能体。用户可以选择“生成复习卡片”“提炼课件重点”或“整理并关联已有笔记”等目标，智能体将目标转化为可执行步骤，按需调用PDF文本提取、OCR识别、个人资料检索和内容生成工具，并结合工具反馈调整后续步骤。整理结果先作为候选摘要、标签和卡片展示，经过用户确认后写入个人知识库。设置工具白名单、执行步数上限和结果校验，并保存可供用户查看的执行记录。

3. 实现知识组织与关联展示。将摘要和知识点转化为可编辑的卡片，为卡片记录原资料及页码或文本片段；结合学科、标签和语义关联推荐已有知识卡片，通过思维导图、卡片编排和关系图辅助用户梳理学习内容。关联推荐由用户确认或修正，不将模型生成关系直接认定为客观事实。

4. 完成平台管理与统计功能。提供用户管理、敏感内容审核、解析任务监控和聚合统计，展示资料数量、学科分布、AI调用次数与任务处理状态，为平台维护和毕业设计演示提供支持。

5. 验证系统可用性与整理效果。围绕功能正确性、双端数据一致性、权限隔离、任务异常处理和AI输出质量开展测试，并记录真实测试环境、样本来源和评价结果。

## （二）主要研究内容

首先开展需求分析，明确普通用户与管理员的权限边界，梳理课堂拍照、碎片记录、批量上传、资料查阅和复习整理等场景，形成业务流程、功能需求和非功能需求。随后设计前后端分离的整体架构，将用户、资料、标签、知识卡片、卡片关联、解析任务、通知和调用记录等业务对象映射为数据库实体，依据实际关系确定表结构。

其次研究双端协同方式。两端通过统一API访问同一套业务数据；图片和PDF本体存入文件存储，MySQL保存资料元数据、权限信息和处理结果。资料上传完成后创建异步解析任务，前端读取任务状态，避免长时间等待模型返回。对于两端编辑同一笔记的情况，拟使用版本号校验与冲突提示，防止静默覆盖用户修改。

再次设计学习资料整理智能体，将其作为系统的智能处理模块，由Spring Boot管理任务、权限及工具执行，大模型负责理解整理目标、提出步骤和生成候选内容。流程拟划分为目标输入、任务规划、工具执行、结果校验与确认保存五个阶段。例如，用户上传一份课件并要求生成复习卡片，系统先确定资料类型与文本获取方式，再分段提取要点、生成卡片，按需检索已有笔记并提出关联建议，最后检查格式与来源定位。PDF已有文字层时优先直接提取；课件截图及扫描页调用OCR；长资料按章节或页段切分，保留页码和片段标识。工具反馈不足时，智能体可在执行上限内调整步骤或请求用户补充信息。

智能体的操作范围限定在当前用户授权资料内。模型提出的工具名称和参数必须经过服务端白名单与权限校验，不能直接执行任意命令或SQL。来源页码和片段标识以解析工具产生的实际记录为准，后端检查标识是否存在及是否属于当前资料，事实一致性还需通过原文对照和人工评价检查。候选结果通过校验后供用户预览、修改与确认，保存操作由明确的业务接口完成；模型不直接执行删除资料等破坏性操作。任务记录包含目标、步骤状态、工具名称、耗时及异常信息，记录的是可观察的执行过程，不要求展示模型内部思维。

最后完成界面实现、管理统计、功能测试和效果评价。开发按最小闭环推进：先完成登录、资料上传和双端查阅，再加入AI解析、知识卡片与可视化，最后完善管理统计和异常处理。研究重点是应用流程与工程实现，不涉及训练基础大模型。

## （三）主要功能模块概述

### 1. 用户与双端协同模块

（1）账户管理：提供账户登录、个人信息维护及微信身份绑定入口，两端使用统一用户标识访问个人资料。

（2）权限与同步：普通用户管理本人资料；管理员执行授权范围内的管理操作。资料修改后两端读取统一数据，对并发编辑进行版本校验与冲突提示。

### 2. 资料采集与管理模块

（1）小程序采集：拍照或选择图片上传课件截图，快速录入课堂要点与碎片笔记，填写标题、学科和初始标签。

（2）Web集中管理：批量上传PDF，查看原文及解析状态，按标题、学科和标签筛选资料，完成搜索、收藏、编辑、归档和删除。通过文件摘要值识别同一用户的重复上传并给出提醒。

### 3. 学习资料整理智能体模块

（1）目标输入与任务规划：提供常用整理目标及文字补充入口，将用户需求转换为步骤清单，展示当前执行阶段。基础交付聚焦资料整理，不扩展为通用聊天助手。

（2）工具调用与反馈：注册PDF文本提取、图片OCR、个人资料检索、摘要及卡片生成等工具。根据资料类型和整理目标选择工具，解析执行结果，必要时调整步骤；工具参数和访问范围由后端校验。

（3）结果校验与确认保存：生成包含摘要、标签、知识点、来源定位和候选关联的结构化结果，检查必填字段及来源标识，提供原文对照、人工编辑和确认保存入口。关联推荐说明对应资料和文本依据。

（4）任务与异常管理：展示待处理、处理中、待确认、已完成、失败及已取消状态；设置超时、执行步数上限、有限重试和幂等保存，记录调用次数、耗时及失败原因，支持用户取消尚未完成的任务。

### 4. 知识卡片与可视化模块

（1）卡片管理：双端查看知识卡片及摘要，支持收藏、搜索和简单编辑；Web端提供拖拽编排，保存用户调整后的卡片顺序与位置。

（2）关系展示：根据提炼结果展示层级思维导图，将卡片及其关联映射为节点和连线，支持查看关联依据、确认推荐、删除不合理关系，并跳转至原资料。图谱定位为个人知识卡片关联展示。

### 5. 通知与用户反馈模块

（1）解析提醒：完成或失败时生成站内通知。微信订阅消息在用户授权且存在可用消息模板的条件下接入，未授权用户仍可在任务列表查看结果。

（2）结果纠正：用户可修改摘要、标签和卡片内容，保留必要的修改信息，便于区分AI生成与人工确认的结果。

### 6. 管理后台与统计大屏模块

（1）后台管理：提供用户状态管理、敏感内容审核及审核记录、资料元数据查看和解析失败任务检查。资料内容访问遵循最小权限原则，审核操作留痕。

（2）数据统计：以聚合指标展示平台资料量、热门学科、上传趋势、AI调用次数和任务成功率。明确时间范围与指标口径，区分实际调用与重试调用，避免通过统计界面泄露私人笔记。

## （四）拟解决的关键问题与课题特色

关键问题包括：多类型学习资料的统一采集与解析；智能体工具调用的可控执行；AI生成内容与原始资料的对应关系；双端编辑与处理状态的一致性；关联关系的可解释展示。课题特色体现在将移动采集与桌面整理衔接，将智能体能力落实为可记录的工具调用与反馈流程，并将生成结果与来源定位、人工修正相结合。这些属于拟开展的应用设计，不预先宣称算法创新或性能优势。

## （五）论文（设计）提纲

第一章 绪论：介绍选题背景与意义、国内外研究现状、研究内容及论文组织。

第二章 相关技术：介绍Spring Boot、MyBatis-Plus与MySQL、Vue3与微信小程序、大模型API、OCR及智能体工具调用技术。

第三章 系统需求分析：分析用户角色、典型场景、功能需求、非功能需求及可行性。

第四章 系统总体与详细设计：阐述系统架构、数据库、双端协同、智能体整理流程、知识关联及权限设计。

第五章 系统实现：说明资料采集管理、异步解析、工具调用、知识卡片、关系可视化、后台统计与通知功能的实现。

第六章 系统测试与分析：展示功能测试、异常处理、双端一致性及资料整理效果评价，分析局限。

第七章 总结与展望：总结实际完成的工作，说明不足及后续改进方向。

# 三、研究方法和手段

## （一）研究方法

1. 文献研究法。围绕大模型智能体、文档图像理解、检索增强、知识可视化与教育应用检索近五年文献，核对作者、题名及出版信息，比较不同技术路线的适用范围，为功能设计和评价指标提供依据。

2. 场景与需求分析法。以学生课堂记录、课后整理与复习查阅为典型场景，梳理双端操作步骤与数据流转关系。后续结合自用体验及可获得的用户反馈修订需求，未开展调研前不编造访谈、问卷或样本数据。

3. 系统设计与原型实现法。采用前后端分离和分层设计，将资料管理、异步任务、智能体工具和知识展示划分为职责清晰的模块，通过原型验证页面交互，再逐步实现业务闭环。

4. 对照测试与人工评价法。拟使用合法取得的PDF、课件截图和文字笔记建立测试集，记录样本来源、长度及清晰度。对同一资料和整理目标比较固定流程与智能体流程，尽量保持模型版本、基础提示、工具集合和输入内容一致，考察工具选择是否符合资料类型、任务是否完成、发生异常后能否恢复，以及耗时、调用次数和实际费用。针对摘要检查事实一致性与要点覆盖；针对知识卡片检查来源可追溯性；针对关联建议由人工判断其合理性。另对超时、OCR空结果、输出字段缺失、无权限检索和重复保存等场景进行异常测试。样本数量和结果在实际测试后报告，不预设智能体优于固定流程。

## （二）技术选型分析

1. 后端采用Spring Boot。其应用组织方式便于构建统一业务API，结合分层结构管理用户、资料和解析任务。拟优先采用模块化单体部署，减少微服务拆分带来的运维负担，并通过独立接口封装AI服务调用。

2. 数据库采用MySQL，数据访问采用MyBatis-Plus。用户、资料归属、标签关联和任务记录具有明确的结构化关系，适合关系数据库存储；MyBatis-Plus用于常规数据操作与分页，复杂统计仍依据实际需求编写查询。文件本体与数据库元数据分别存储，卡片来源与关联信息保持可追溯。

3. Web端采用Vue3和Element Plus。Vue3用于组织资料列表、解析详情和卡片等交互页面，Element Plus用于表单、表格与后台管理组件。统计图表、层级结构和卡片关系图拟采用ECharts呈现，卡片拖拽编排由专门的交互组件实现，避免将图表展示与业务编辑混为一体。

4. 移动端采用原生微信小程序。围绕拍照、选图、上传及轻量编辑开发页面，与Web端共用后端接口。订阅消息以平台能力、账号条件和用户授权为前提，站内通知保留为基础提醒方式。

5. AI采用公有大模型API与OCR接口。学习资料整理智能体通过目标理解、任务规划、受限工具调用、执行反馈和结果校验组织处理流程。后端封装工具注册、参数校验、任务上下文与执行循环，模型支持工具调用时使用相应接口，不支持时以结构化动作协议对接并校验。重点实现输入预处理、结构化生成和来源检索，不训练基础模型。大模型与OCR服务采用可替换接口封装，具体厂商根据可用性、输出质量和实际成本确定。API密钥保存在服务端，对文件上传、访问归属及工具参数进行校验；向外部服务提交资料前向用户说明处理方式，仅发送完成任务所需内容。

## （三）可行性与实施保障

技术上，课题围绕已有Web与小程序开发能力及外部AI接口组织应用，研究重点集中于业务流程与系统集成。实施上，分阶段完成上传查阅闭环、智能整理闭环和可视化管理，资料问答与复习计划暂不列为基础交付。资源上，使用合法取得的学习资料和测试账户，先以小规模测试验证API可用性与成本。针对OCR误识别、模型超时和输出不完整等风险，设置原文回看、人工修正、任务重试与失败提示；对于复杂公式、手写内容和低清晰度图片，明确识别边界并记录测试表现。

# 五、文献综述

围绕个人学习资料整理，本课题检索并核对了智能体、文档理解、检索增强和教育应用等方向的相关研究。从已获得的研究内容看，主要技术路径包括利用大模型生成摘要与标签、通过外部工具取得文本或执行操作、检索已有资料补充上下文，以及以图结构组织知识关系。上述研究为系统实现提供了依据，但其研究对象、任务规模和评价方式不同，不能直接据此判断一个双端资料整理系统已具备实际学习效果。

卢宇等提出基于大模型的教学智能体框架，围绕教育任务设定、规划、能力拓展、记忆与反思组织功能，并讨论其在项目式学习中的作用[1]。该研究启发本课题以明确的整理任务组织AI能力，使资料处理过程具有目标、执行步骤和用户反馈。Yao等提出ReAct，将推理与任务动作交替组织，并结合环境返回的信息调整后续操作[2]。本课题拟借鉴其工具交互思路，通过工具调用记录、输入输出和任务状态体现执行过程，而不是要求平台展示模型内部的思维过程。

冯掌印等从检索时机规划、检索技术和检索结果利用等方面综述大模型时代的检索增强方法，并整理评价方式与应用方向[3]。这一研究提示，本课题的关联推荐应考虑何时检索、检索什么和如何展示依据。吴永和等讨论大语言模型支持的多智能体技术及教育应用，提出感知、认知与执行能力框架，并分析稳定性和安全等挑战[4]。考虑本课题的开发规模，拟优先实现单智能体与受限工具协作，将多智能体作为后续扩展研究方向。

Wang等从智能体构建、应用与评价角度形成综述框架[5]；郭先会等讨论智能体分类、组成、构建方法与有效性评估[6]；周涛等梳理大模型智能体的概念、发展前沿和产业实践[7]。这些研究共同说明，智能体应用需要明确其感知对象、决策范围与执行接口。Schick等的Toolformer研究模型对外部API的选择与使用[8]，为工具调用提供了方法参考。本课题使用公有模型已有能力完成工具选择，不复现Toolformer的模型训练，也不据此声称实现了模型自主学习。

文档处理方面，张言等综述以文字为中心的图像理解技术[9]，林泽柠等总结视觉信息抽取方法、数据集与评价指标[10]。两项研究表明，获取图像中的文字与理解文字在版面中的关系是相关但不同的任务。本课题拟首先完成课件截图和扫描PDF的文字获取，再保留页码与片段信息用于摘要和卡片生成；复杂公式、图表和手写内容可能影响解析质量，需要在测试中单独观察，不能将OCR输出一律视为正确原文。

在教育应用与知识展示方面，余胜泉、熊莎莎提出通过检索、外部智能组件与知识图谱等增强大模型教育应用的架构[11]，强调通用生成能力在教育任务中仍存在局限。刘玉华等从可视化表达、知识构建与应用分析角度综述知识图谱可视分析[12]，为知识关系展示提供参考。本课题拟把可视化落实为卡片层级与关联关系，并提供查看来源、人工确认和删除关系的操作，避免仅以节点数量或视觉复杂程度衡量整理质量。

可靠性方面，刘泽垣等分析大语言模型幻觉的来源、评价与缓解方法[13]，提示生成文本的语言流畅度不能替代事实正确性评价。兰国帅等讨论生成式人工智能教育应用中的争议、促进方法与未来议题[14]，为用户自主判断、资料隐私和负责任使用提供参考。Gao等综述检索增强的检索、生成与增强环节[15]，支持将用户资料作为生成依据；Liu等发现其研究中的模型对长上下文不同位置的信息利用存在差异[16]，为本课题采用分段处理和明确来源提供了参考，但这一结论不直接等同于所有现有模型的表现。

综合上述研究，面向本课题仍需解决的工程问题是：将多类型资料采集、可控AI整理和知识关系展示整合到一致的双端流程中；为生成结果提供可核查来源；在识别失败、接口超时和并发编辑等情况下保持可用性。本课题拟以统一后端和异步任务为基础，构建受限工具调用的资料整理智能体，并结合来源定位、人工修正和真实对照测试评价方案。研究成果以实际实现范围和测试记录为准，不预先推断学习成绩改善或通用算法优势。

# 六、工作进度安排

以下采用相对周次安排，具体起止日期根据学校毕业设计日程确定。
