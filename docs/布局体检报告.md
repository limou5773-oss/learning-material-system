## 一、结论先说

布局**结构**是合理的：一屏一个主任务、内容有宽度上限、正文左对齐、分组靠留白、断点按内容断。问题不在骨架，在**三个可量化的细节**：正文字号偏小一档、卡片间距小于内边距、主色块用得太散。

下面所有数字都是在 1512×950 视口下用 CDP 读取 `getComputedStyle` 与 `getBoundingClientRect` 实测的，不是目测。

## 四、为什么正文字号停在 13.5 而不是 14

技能给的是「桌面正文 ≥14px」。实测卡片摘要 12.5px 确实偏小，但直接拉到 14 会让卡片高度涨约 12%，一屏可见的卡片从 2.5 行降到 2 行，反而增加滚动成本。

折中到 13.5px（卡片）、13px（任务行与通知），配合 1.8 行高，实测行宽 29 字落在舒适区。**这是一个明确偏离硬指标的决定，理由是信息密度。**

如果答辩演示用 1080p 投影，13.5px 在投影上会明显偏小，那种场合应该直接改回 14px——把 `.material-item-main p { font-size: 13.5px }` 改成 14 即可，一行。

## 五、两次「改了没生效」的真实原因

改的过程中有两处规则写进 `style.css` 后没有反应，记下来避免再踩：

1. **全局层压不过组件 scoped**：`.task-list .material-item-main p`（0,3,1）与组件内同名规则（0,3,1 + `[data-v-xxx]`）打平，而组件样式在运行时注入、顺序更靠后，所以全局的输。这两处（任务行字号、个人中心宽度）最终是**改组件内的 scoped 样式**解决的，而不是加 `!important`。
2. **单类选择器压不过后代选择器**：`gap: 18px` 挂在 `.document-grid`（0,1,0）上，但样式表里早有 `.library-layout .knowledge-grid { gap: 16px }`（0,2,0），所以怎么改都不动。最终提成 `.main-area .document-grid`（0,2,0）才生效。

判断方法：`getComputedStyle` 拿到的是结果，配合遍历 `document.styleSheets` 打印命中的规则，比反复改 CSS 猜快得多。

## 六、布局骨架评估（为什么说结构是合理的）

对照技能的「五种页面骨架」：

- **后台列表页**（资料 / 卡片 / 任务 / 通知 / 用户 / 审核 / 任务监控）：顶部标题 + 筛选栏 + 列表 + 分页，主操作在右上。符合范式。
- **设置页 / 表单页**（新建笔记、编辑卡片、上传、个人中心）：单列或两列表单，操作栏 sticky 在底部。符合「主按钮放视线终点」。
- **工作台**（详情页）：内容居中单列、动作分组、危险动作隔离在右侧。符合。
- **认证页**：非对称两栏，主任务（登录）在右栏窄卡。符合「一屏一任务」。

唯一与范式有偏差的是**统计大屏**：4 张指标卡 + 图表 + 说明面板，信息密度高、缺少明确的「下一步该做什么」。但大屏本身就是只读的监控页，不需要主任务，属于合理例外。

## 七、剩余问题

1. **统计页环形图图例重叠**：canvas 内部绘制，190px 宽卡片里图例压住圆环。需改绘制逻辑，不在样式层范围。
2. **通知页顶部提示条**：`微信订阅消息尚未开通，站内通知正常` 长期占据一行，对用户是低价值信息（每次进来都看到），建议折叠成图标 + tooltip，或只在未开通时首访提示一次。
3. **管理端表格窄屏**：≤920px 横向滚动，未做卡片化改造。后台惯例可接受，但移动端体验一般。
4. **间距清扫未完成**：组件内仍有 15/19/22 等非 4/8 值，量小、不影响整体节奏，未强行统一。
