## 1 已确认的接口缺口

OpenAPI 声明了 54 个“HTTP 方法 + 路径”操作，当前 Controller 声明匹配 49 个，缺少下列 5 个。该数字只表示路由声明对应关系，不是功能完成率，也不证明已有接口全部运行正常。

| 方法 | 路径（统一前缀 /api/v1） | 缺少能力 |
| --- | --- | --- |
| DELETE | `/cards/{id}` | 按版本删除本人知识卡片 |
| DELETE | `/users/me/wechat-binding` | 验证本人密码后解除微信绑定 |
| PATCH | `/users/me` | 个人昵称或密码修改 |
| POST | `/auth/wechat-sessions` | 用微信临时 code 登录已绑定账号 |
| POST | `/users/me/wechat-binding` | 将微信身份绑定至当前账号 |

证据：需求第3.3节列出个人中心资料修改；第9.2节明确 PATCH /users/me 及卡片 DELETE 接口；F02规定微信登录、绑定和解绑。当前 AuthController 只有注册、密码登录、退出和 GET /users/me，CardController 没有 DeleteMapping。Web MeView 与小程序“我的”也未提供资料修改/微信绑定操作。AuthDtos 的 hasWechatBinding 目前固定为 false。

## 3 已实现与实测不足要分开

- DeepSeek、腾讯OCR和agent已配置启用，但本轮未核验到真实资料处理、模型规划、失败反馈、引用人工评价和真实费用的完整验收记录。不能用此前模拟响应或测试数据代替。
- 微信开发者工具登录页本轮重新编译后已显示；尚不能据此认定登录、拍照上传、预览、双端编辑冲突、候选确认和通知跳转均通过。
- 微信订阅发送是未实现的可选渠道；站内通知已实现。微信身份绑定则是F02必须补齐的功能，不能归为“只缺密钥”。
- 资料删除与卡片删除是不同能力：前者已有，后者虽然列入OpenAPI但尚无实现。
- 性能目标、真实效果评价、部署与备份恢复没有本轮实测证据。

## 4 文档与工程约定仍需同步

- 最新代码已采用 controller / service / service/impl / mapper / entity / dto / util 分层，23组业务接口与实现类；需求第6.3节仍保留初稿目录，并含“未创建业务工程”的过时文字。
- 文档仍有环境变量和Flyway分批迁移描述，当前用户已选择原 application.yml 直接配置、合并SQL手动初始化。应记录经过用户确认的变更，并同步说明；不能靠删除需求来掩盖未实现功能。
- 已引入 MyBatis-Plus starter，但当前 CRUD 主要是 MyBatis 注解SQL，统计使用 JdbcTemplate。没有统一采用 BaseMapper 通用CRUD；这是技术落实方式差异，不等同于相关业务功能不存在。
- 文档初始建议模型尝试上限12次、单次外部请求超时60秒；当前生成服务对agent总模型尝试限8次、规划尝试限4次、生成尝试限2次，模型客户端45秒、OCR客户端20秒。需把已有实施约定与基线的建议值同步，不能将其写成完全一致。
