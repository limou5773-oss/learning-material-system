## 二、与原方案的 3 处必要偏差

### 1. 归档计数改成静态入口（P3）

方案里写的是“列表页查一次 `status=ARCHIVED&pageSize=1` 拿 count”。实施时发现 `tests/web-admin-users.test.js:279` 有一条硬断言：

```js
assert.deepEqual(reads, ['tags', 'materials'], '实际资料SFC挂载同时读取标签和列表')
```

它要求资料页挂载时**恰好两个请求**。多加一个请求会直接让 2 条用例失败，而这两条用例测试的是 401 竞态，与归档无关。

**改为不增加请求的静态入口**：筛选结果行右侧显示“已归档的资料不在此列表 [查看已归档]”，点击切到 `status=ARCHIVED`。信息量少一点，但不破坏并发竞态的测试契约，也不增加首屏开销。

### 2. `isCurrent` 的语义必须同步调整（P2）

这是方案里没预见到、实施时必须补的。原判定：

```java
!"SUPERSEDED".equals(status) && materialVersion == currentMaterialVersion && materialStatus != "DELETED"
```

`patch()` 每次都会 `version = version + 1`。若只让“内容变更才失效”，改标题后 `material.version` 从 2 变 3，而审核单的 `material_version` 仍是 2 —— 审核单 `status` 还是 `APPROVED`、AI 也能用，但 `isCurrent=false`，前端会显示“已失效”。

**矛盾状态**：明明能用，界面说失效。所以 `isCurrent` 改为：

```java
!"SUPERSEDED".equals(status) && !"DELETED".equals(materialStatus)
```

语义从“版本号是否对得上”变成“这条审核结论是否仍然有效”。因为“版本变了要失效”这件事已经由 `supersede` 机制承担，不再需要二次校验。实测改标题后 `isCurrent=true`、改正文后 `false`，两边一致。

### 3. 新增 `supersedePendingByMaterial`（P2）

如果元数据变更完全不碰审核单，会留下**僵尸待审单**：

- 资料 v1 送审 → PENDING
- 改标题 → 资料 v2，待审单仍是 v1
- 管理员批准 → `lock()` 里 `material.version != review.materialVersion` → 409，永远批不了
- 作者可以重新送审 v2，但旧单一直挂在管理员列表里

所以元数据变更时把 PENDING 置为 `SUPERSEDED`（不碰已通过的、不改 `access_state`、不发通知）。这样既不留僵尸单，也不影响已通过的结论。

## 四、风险与回滚

| 风险 | 说明 | 处置 |
|---|---|---|
| `isCurrent` 语义变化 | 老数据里若存在“APPROVED 但版本落后”的单，现在会显示为有效 | 已核对：V18 迁移后库中只有一条此类数据（资料 4 → 现已 RESTRICTED 且审核单 SUPERSEDED），无异常 |
| 元数据修改不再递增“审核有效期” | 用户改标题后审核仍有效，这是本次的设计目标 | 若答辩时被质疑，可解释为“审核绑定正文内容，不绑定展示信息” |
| PENDING 单被静默失效 | 元数据变更会使待审单失效，作者需重新送审 | 不做通知，避免与“内容不合规”混淆；审核历史中能看到 SUPERSEDED |
| 前端 URL 变长 | 筛选条件进入地址栏 | 可刷新保持、可分享，属改进 |
| 内存会话 + 整页刷新 | `auth.ts` 设计为仅内存保存，刷新需重新登录 | 既有 D02 设计，未改动；自动化截图必须用 SPA 内跳转 |

回滚方式：本次改动未涉及数据库结构，回滚只需 `git checkout` 以下文件：
`web/src/router.ts`、`LoginView.vue`、`ForbiddenView.vue`、`MaterialDetailView.vue`、`MaterialsView.vue`、`TasksView.vue`、`TaskCreateView.vue`、`OwnerMaterialReview.vue`、`main.ts`、`style.css`，删除 `MaterialMetaDialog.vue`，后端回滚 `MaterialServiceImpl` / `ContentReviewMapper` / `ContentReviewService(Impl)` / `ContentReviewDtos`。
