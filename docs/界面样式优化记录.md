# 界面样式优化记录（Element Plus 组件库）

日期：2026-10-30　范围：`web/` 前端　验证：304/304 前端测试通过、`vue-tsc` 无错误、`vite build` 成功

## 一、做了什么

### 1. 主题层统一（`web/src/style.css`）

新增「Element Plus 主题层」，把品牌色、圆角、控件高度、阴影统一到同一套 token：

- 覆盖 `--el-color-primary` 全色阶、成功/警告/危险/信息色、`--el-text-color-*`、`--el-border-color-*`、`--el-fill-color-*`、`--el-box-shadow*`；
- 控件统一 40px 高（`--el-component-size`）、10px 圆角、`#f8fafd` 输入底色，聚焦态改为「1px 主色内描边 + 3px 淡蓝外发光」；
- 按钮、标签、卡片、表格、分页、空状态、骨架屏、提示条、下拉菜单、消息框逐项对齐现有视觉语言；
- 新增页面级通用类：`.filter-bar`（筛选栏）、`.form-panel`（表单容器）、`.loading-panel`、`.list-pager` 等；
- 用 `:not(.el-button)` 把旧的原生控件样式隔开，避免旧规则污染组件库按钮。

### 2. 组件按需注册（`web/src/main.ts`）

- 注册 `el-input / el-select / el-option / el-checkbox / el-form / el-form-item / el-button / el-alert / el-card / el-tag / el-empty / el-skeleton / el-pagination / el-link / el-dialog / el-config-provider` 与 `v-loading` 指令；
- 中文语言包在根部通过 `h(ElConfigProvider, { locale: zhCn })` 注入，`App.vue` 保持纯净（单元测试直接渲染 `App.vue`）；
- 未全量引入 Element Plus，产物体积 570 KB（gzip 185 KB），比改造前的 711 KB 更小。

### 3. 页面改造

| 页面 | 改动 |
|---|---|
| 我的资料 `MaterialsView` | 搜索/学科/标签/状态 → `el-input`、`el-select`；「只看收藏」→ `el-checkbox`；资料卡 → `el-card`（悬停上浮）+ `el-tag`；收藏 → `el-button`；空态 → `el-empty`；加载 → `el-skeleton`；分页 → `el-pagination`；新增「重置」按钮 |
| 知识卡片 `CardsView` | 同上，另加「仅收藏」并入筛选栏 |
| 整理任务 `TasksView` | 状态筛选 → `el-select`；任务状态 → 彩色 `el-tag`；空态/加载/分页组件化 |
| 新建/编辑笔记、资料详情、卡片详情 | `el-form` + `el-input` + `el-alert` + `el-skeleton` + `el-button`，正文不再重复显示字数（页脚统一计数） |
| 用户管理 / 任务监控 / 内容审核 / 通知 | 保留原生语义结构，仅重做样式：表头带底色与圆角、行悬停高亮、按钮分组、未读徽标用品牌色、提示条改浅蓝底 |

## 二、为什么有些页面是「原生 + 样式」而不是「组件替换」

`tests/*.test.js` 用自定义宿主树直接断言原生 DOM（`select`、`table > tbody > tr`、`a[href]`、`input#id`）。
把用户管理、任务监控、内容审核、通知、卡片编辑改成 `el-table` / `el-select` / `el-menu` 后，**304 项测试中有 200+ 项失败**，因为这些测试并不渲染 Element Plus 的真实内部结构。

因此按「不破坏既有验收契约」的原则处理：

- **被测试锁定的页面**：保留原生控件，仅通过 CSS 统一外观；
- **未被测试覆盖的页面**：替换为组件库控件，享受成熟的交互与状态。

如果后续要把管理端也换成 `el-table`，正确做法是先在 `tests/helpers/element-plus.js` 里补 `el-table / el-select` 的适配器，再改页面，而不是改测试断言。

## 四、答辩可讲的技术点

1. 设计 token 化：颜色、圆角、间距、阴影集中在 `:root`，组件库主题与自研样式共用一套变量，换肤只改一处。
2. 按需引入 + 语言包在根节点注入，兼顾体积与中文环境。
3. 组件库与既有语义化结构共存：不改业务逻辑、不改可访问性属性（`aria-*`、跳过导航、焦点描边），只替换表现层。
4. 用测试约束改造边界：先跑 304 项测试确定「哪些 DOM 结构是契约」，再决定改哪些页面。

# 第二轮：整体排版精修（2026-10-30 晚）

第一轮把控件换成 Element Plus，解决了「形」；第二轮针对实际截图逐页核对后暴露的「排版松、层级弱、控件不成组」问题做结构性调整。

## 一、先截后改：定位真实问题

用无头 Chrome + CDP（`Page.captureScreenshot`）在 1512×950 下走 SPA 路由实测 15 个页面（登录、资料列表、卡片列表、任务、三个上传/新建页、通知、卡片编排、个人中心、资料详情，以及管理端四页），逐张比对后归纳出 7 类共性问题：

| 问题 | 表现 | 处理 |
|---|---|---|
| 筛选栏折行 | 资料页「搜索/重置」被挤到第二行右侧，留一片空白 | 收紧控件宽度与栅格，所有列表页筛选恒定一行 |
| 主按钮不可见 | 新建/编辑页保存按钮在首屏之下，要滚动才看得到 | 操作栏 `position: sticky` 常驻底部，带顶部细线与阴影 |
| 卡片不等高 | 摘要 1 行与 2 行的卡片高度差 40px，网格参差 | 卡片容器改 flex 纵向，正文区 `flex:1`，操作区贴底 |
| 元信息错位 | 标签多时"更新时间"掉到下一行最左侧 | 时间 `margin-left:auto` 恒居右，元信息区加分隔线 |
| 表单空旷 | 单列表单在 1512 宽屏下左右各空 200px | 学科/标签改两列（`.form-row-2`），输入框白底描边 |
| 页面级滚动条压边 | 滚动条贴在窗口右缘，与内容卡片圆角割裂 | 改为「应用内滚动」：侧栏与顶栏固定，仅内容区滚动 |
| 两个主色按钮打架 | 顶栏「新建内容」与页面「新建笔记」同为实心蓝 | 顶栏降级为描边次级按钮 |

## 二、骨架层改动（`web/src/style.css`）

1. **应用内滚动**：`.workspace-shell` 改 `height:100vh; overflow:hidden`，`.main-area` 独立 `overflow-y:auto`。侧栏由「悬浮圆角卡片」改为「贴边白色导航栏」，删掉外层 20px 边距与 24px 圆角，视觉更接近后台工作台。
2. **新增间距标尺**：`--gap-1..7`（4/8/12/16/20/24/32），页面级间距统一按标尺取值，避免 18/21/23 这类随手数字继续扩散。
3. **颜色阶微调**：`--ink` #17253c、`--muted` #66788f、`--line` #e7ecf3、新增 `--surface-3`；正文与次要文字对比度提升一档（12px 灰字此前接近 4.2:1，现约 5.1:1）。
4. **圆角收敛**：`--r-lg` 12→14px，新增 `--r-xl:18px`；卡片统一 14px、控件 10px，不再出现 11/12/13/14/16 混用。
5. **侧栏节奏**：宽 232→240，导航项高 48→42、字号 15→14、图标 14→16，分组标题加 `letter-spacing` 弱化；顶栏 72→64。

## 五、边界与遗留

- **管理端未组件化**：`el-table` 会让 200+ 条断言原生 `table > tbody > tr` 的用例失效，本轮只做 CSS 层统一，结构与 `aria-*` 保持原样。
- **卡片编排画布重叠**：`organization-canvas` 的卡片为固定 260×150 绝对定位，历史上保存过的布局若 y 步进小于 170 会出现轻微重叠——画布允许重叠是拖拽布局的正常行为，未改数据。
- **图表内部**：统计页环形图图例由 canvas 绘制，图例与环图在窄卡片下偏挤，需改绘制逻辑，不在本轮范围。
