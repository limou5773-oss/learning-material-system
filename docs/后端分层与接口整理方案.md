# 后端分层与接口整理说明

2026-10-28：已在原项目完成 Java 包结构整理与 Service/ServiceImpl 分离。本轮按用户要求以结构整理和必要编译为主，不执行完整业务回归或真实厂商联调。

## 目录与职责

根包：`backend/src/main/java/com/learningmaterial/system`。

| 目录 | 职责 | 当前 Java 文件数 |
| --- | --- | --- |
| controller | HTTP 路由、请求绑定、身份与响应处理 | 12 |
| service | 业务接口 | 23，不含 impl |
| service/impl | 业务实现、事务与业务规则 | 23 |
| mapper | 数据访问；包含原统计 Repository | 23 |
| entity | 数据表映射与查询结果对象，保留原 Row 类名 | 19 |
| dto | 请求、响应与内部数据传递对象 | 21 |
| util | 资源 ID、文件校验、JSON 转换及审核错误约定 | 5 |
| config | 安全、模型、OCR 与管理员初始化配置 | 4 |
| security | 身份对象与 Bearer 认证过滤器 | 2 |
| integration | DeepSeek、腾讯 OCR、文件存储适配 | 9 |
| task | worker、任务处理器与受限工具协议 | 10 |
| common | 统一响应、异常处理与请求 ID | 5 |

## 调用关系

```text
AuthController
    → AuthService（接口）
        → AuthServiceImpl（@Service 实现类）
            → UserMapper / SessionMapper
                → UserRow / SessionRow
```

Controller 依赖 Service 接口，不直接依赖 Mapper 或 ServiceImpl。23 个业务实现类均实现对应接口，原有事务注解保留在实现类。业务类之间同样通过接口注入；MockTaskProcessor 原有手动 new 来源准备服务已改为接口注入。

原来 Service 中的 11 个公开数据记录已移到 dto，例如 TaskLease、SourceDraft、CardView、PdfExtraction 和 PreparedTaskSource。Service 接口保留业务方法和既有业务常量。现有 *Dtos 聚合类中的嵌套 record 保留，不为目录整理重复定义同一数据类型。

## 本轮保留的契约

- 保留 12 个 Controller 的 HTTP 路径和方法，已有资源式接口继续使用；整理 Java 包不要求修改双端 API 地址。
- 保留 Mapper SQL、生成主键配置、原业务校验与事务边界。
- 数据实体不直接作为普通 HTTP 接口响应，接口继续使用现有返回对象与统一响应结构。
- 仅因跨包引用而公开必要的现有 DTO 转换方法和工具协议类型；未删除校验或扩展业务能力。
- MyBatis-Plus 依赖保持现状，本轮没有把全部注解 SQL 改写为 BaseMapper；统计查询仍使用 JdbcTemplate，归入 mapper 数据访问层。分层结构与 ORM 用法统一是两个独立事项。
- 本轮 Java 整理没有修改 application.yml 或数据库脚本；用户已有本机配置和数据库脚本调整保留。
