# 首个管理员与用户管理

管理员初始化直接修改原YAML，旧环境脚本已移除。

更新日期：2026年10月26日。D21只提供账号元数据、用户启停及操作审计，不授予管理员任意查看私人笔记、提示词或资料正文的能力。审核授权与正文访问留待D22。

## 首次创建管理员

直接在原 `backend/src/main/resources/application.yml` 的 `lms.admin-bootstrap` 填写 username、password、display-name，并仅为首次初始化设置 enabled=true。账号6—32位字母/数字/下划线，密码8—64字符且UTF-8不超过72字节；成功后把enabled改回false并清空初始化密码，再正常启动。

没有默认管理员密码，不提供网页提权接口。已有管理员或用户名占用时明确拒绝初始化。正常使用的登录密码由数据库保存BCrypt摘要，清空的是初始化配置中的明文，不是删除账号。

## 用户管理

管理员登录Web后可进入“用户管理”，按用户名/显示名称的字面子串及状态筛选，查看用户ID、账号、显示名、角色、状态和注册时间。服务端返回既有User七字段，微信绑定只返回布尔标记；不会返回密码散列、会话令牌摘要、openid或密钥。

启用或停用前选择账号、目标状态并填写最多1000 UTF-16单元的非空原因，核对后明确提交。状态更新、会话撤销和USER_STATUS审计在同一短事务中完成；审计保存操作者、目标账号、原状态、新状态、原因与时间。即使目标已是该状态，明确提交仍保留操作记录。没有角色授予或批量账号变更功能。

停用提交后，该用户的Web和小程序已有会话均失效，后续请求401；登录也被拒绝。重新启用不会恢复旧token，必须重新登录。已经开始处理的请求不会被强行中断；管理写操作在事务内重新核验操作者和会话，不能用等待期间已被撤销的身份完成变更。

禁止停用当前操作账号或最后一位启用管理员；两个管理员并发互相停用时至少保留一位启用管理员。写入失败保留页面中的账号、状态和原因；409需要人工核对，不能自动覆盖或重试。操作成功后若列表刷新失败，会分别提示已保存及读取失败。

普通用户无法通过直接访问Web地址、伪造角色字段或直接调用管理接口取得权限；管理API返回403，无效会话返回401。D21未增加小程序管理后台，仅验证已有小程序会话被停用后失效并返回登录。

自动化、并发、真实HTTP和浏览器证据见[D21记录](../tasks/evidence/D21.md)。微信原生验收和真实模型/OCR联调仍保持既有待办，不能以本机功能测试代替。
