## 二、必须改

### P1 登录后落地页是「个人中心」

**现状**

- `web/src/router.ts:32`
  ```ts
  { path: '/', redirect: () => session.value?.user.role === 'ADMIN' ? '/admin/statistics' : '/me' }
  ```
- `web/src/views/LoginView.vue:28`
  ```ts
  const defaultHome = session.value.user.role === 'ADMIN' ? '/admin/statistics' : '/me'
  ```
- 而学习空间的品牌入口是 `/materials`：`layouts/LearningLayout.vue:13` 写的是 `home="/materials"`。

**为什么不符合使用**

同一个产品里存在两个「首页」：点左上角品牌去资料列表，登录成功却去账号设置页。用户每次登录都要多点一次才能开始干活；首次使用时看到「修改密码 / 退出登录」，会误以为系统只有账号功能。

**改法**

1. `router.ts:32` 改为：
   ```ts
   { path: '/', redirect: () => {
       if (!session.value) return { name: 'login' }
       return session.value.user.role === 'ADMIN' ? '/admin/statistics' : '/materials'
     } }
   ```
   > **注意**：未登录时**必须返回路由对象 `{ name: 'login' }`，不能返回字符串 `'/login'`**。因为 `LoginView.vue:29-33` 会把 `redirect` 参数原样使用，若 URL 变成 `/login?redirect=/login`，登录成功后会被送回登录页，形成死循环。

2. `LoginView.vue:28` 改为：
   ```ts
   const defaultHome = session.value.user.role === 'ADMIN' ? '/admin/statistics' : '/materials'
   ```
3. `LoginView.vue:32-33` 里的特判 `['/', '/me'].includes(requested)` 同步加入 `/materials`，避免管理员被带到学习空间再被守卫踢回（虽然最终结果一致，但会多一次跳转闪烁）。

**影响面**

- 纯前端，后端无改动。
- 我核查过 8 个 web 测试文件，**没有针对 `/` 默认跳转的断言**（`grep '/me'` 只命中小程序测试的 `/pages/me/index`）。风险低，但仍需重跑确认。

### P2 PDF / 图片资料无法修改标题、学科、标签

**现状**

`MaterialDetailView.vue:150`：
```vue
<el-button v-if="material.type === 'NOTE'" @click="router.push(`/materials/${material.id}/edit`)">编辑笔记</el-button>
```

只有 `NOTE` 有编辑入口。PDF 和图片上传后，标题、学科、标签一旦填错，**前端没有任何补救手段**，只能删除重传——但删除是软删除，原文件仍在库里，等于制造垃圾数据。

**后端其实已经支持**

`MaterialServiceImpl.patch():200-210` 对 `title / subject / tags / summary / status` 完全不区分资料类型，只禁止非 NOTE 传 `noteText`：

```java
if (!note && patch.hasNoteText()) throw invalid("UNSUPPORTED_NOTE_TEXT", "文件资料不能填写笔记正文");
```

所以这是**纯前端缺口**，不需要动后端。

**改法**

新增一个轻量弹窗组件 `web/src/components/MaterialMetaDialog.vue`：

```vue
<script setup lang="ts">
import { reactive, ref, watch } from 'vue'
import { api } from '../api'
import type { Material } from '../materials'

const props = defineProps<{ material: Material | null }>()
const emit = defineEmits<{ updated: [Material] }>()
const open = defineModel<boolean>('open', { default: false })
const form = reactive({ title: '', subject: '', tags: '' })
const saving = ref(false)
const error = ref('')

watch(open, value => {
  if (!value || !props.material) return
  form.title = props.material.title
  form.subject = props.material.subject || ''
  form.tags = props.material.tags.map(t => t.name).join('，')
  error.value = ''
})

async function submit() {
  if (!props.material || saving.value) return
  const tags = form.tags.split(/[,，]/).map(v => v.trim()).filter(Boolean)
  if (!form.title.trim()) { error.value = '标题不能为空'; return }
  if (tags.length > 10) { error.value = '最多添加 10 个标签'; return }
  saving.value = true
  try {
    const updated = await api<Material>(`/materials/${props.material.id}`, 'PATCH', {
      version: props.material.version,
      title: form.title.trim(),
      subject: form.subject.trim(),
      tags,
    })
    emit('updated', updated)
    open.value = false
  } catch (cause) {
    error.value = cause instanceof Error ? cause.message : '保存失败'
  } finally { saving.value = false }
}
</script>
```

详情页把「编辑笔记」拆成两个入口：

```vue
<el-button v-if="material.type === 'NOTE'" @click="router.push(`/materials/${material.id}/edit`)">编辑正文</el-button>
<el-button v-else @click="metaOpen = true">编辑信息</el-button>
```

> **先读第四节再动手**：这个 PATCH 会触发审核失效，行为需要先决策。

**影响面**

- 前端新增 1 个组件 + 详情页 2 行改动。
- `version` 必须带上，否则后端 `patch():198` 直接 409。并发编辑时要靠这个返回冲突。

### P3 归档后资料「凭空消失」

**现状**

- 列表默认筛选 `MaterialsView.vue:15`：`const status = ref('ACTIVE')`
- 详情页归档 `MaterialDetailView.vue:66-76`：PATCH 成功只更新本地对象，**没有任何提示**。
- 用户点「← 返回资料」→ 列表重新挂载 → 默认只看 ACTIVE → 刚归档那份不见了。

**为什么不符合使用**

「归档」在产品语义上是「收起来」，不是「删掉」。但用户感知到的结果和删除完全一样：列表中消失、无任何说明。这个误解在答辩演示时一旦发生，需要现场解释很久。

**改法**

1. **详情页给明确反馈**（必做）
   ```ts
   import { ElMessage } from 'element-plus'
   // changeArchive() 成功后：
   if (current()) {
     material.value = updated
     ElMessage.success(updated.status === 'ARCHIVED'
       ? '已归档。可把列表筛选切到「已归档」找回。'
       : '已恢复使用。')
   }
   ```
   样式无需额外引入——`main.ts:9` 已全量引入 `element-plus/dist/index.css`，`ElMessage` 是函数式调用，不占体积也不需注册。

2. **列表页给回流入口**（建议同时做）
   筛选栏已有 `status` 下拉（含「已归档」），但用户不会主动去翻。在列表摘要行补一个可点击的计数：
   ```ts
   // 与 load() 并行，一次轻量请求
   const archivedCount = ref(0)
   async function loadArchivedCount() {
     if (status.value === 'ARCHIVED') return
     try {
       const page = await api<Page<Material>>('/materials?status=ARCHIVED&page=1&pageSize=1')
       archivedCount.value = page.total
     } catch { archivedCount.value = 0 }
   }
   ```
   ```vue
   <span v-if="archivedCount > 0" class="archived-hint">
     另有 {{ archivedCount }} 份已归档资料
     <el-button link type="primary" @click="status = 'ARCHIVED'; search()">查看</el-button>
   </span>
   ```

**影响面**

- 纯前端。列表多一个 `pageSize=1` 的请求，可接受。
- 若不想加请求，只做第 1 步也能解决核心误解。

## 三、建议改

### P4 筛选条件与页码不持久

**现状**

`MaterialsView.vue:12-22` 的 `keyword / subject / tagId / status / page` 全是本地 `ref`，初始值硬编码；`load()` 只把状态拼进请求，**从不写回 URL，也不从 URL 读**。`TasksView.vue:12-13` 同样。

**为什么不符合使用**

搜索「光合作用」→ 翻到第 2 页 → 点开一份 → 点「← 返回资料」→ 组件重新挂载 → 搜索词、页码、标签筛选全部归零。用户需要重做一遍刚才的操作。这是列表页最高频的动作。

**改法（URL 为唯一真相）**

1. 初始化从 query 读：
   ```ts
   const q = route.query
   const keyword = ref(typeof q.keyword === 'string' ? q.keyword : '')
   const subject = ref(typeof q.subject === 'string' ? q.subject : '')
   const tagId = ref(typeof q.tagId === 'string' ? q.tagId : '')
   const status = ref(typeof q.status === 'string' ? q.status : 'ACTIVE')
   const favoriteOnly = ref(q.favorite === 'true')
   const page = ref(Math.max(1, Number(q.page) || 1))
   ```
2. `search()` / `changePage()` 里同步 query（用 `replace`，避免污染后退栈）：
   ```ts
   function syncQuery() {
     const query: Record<string, string> = {}
     if (keyword.value.trim()) query.keyword = keyword.value.trim()
     if (subject.value.trim()) query.subject = subject.value.trim()
     if (tagId.value) query.tagId = tagId.value
     if (status.value !== 'ACTIVE') query.status = status.value
     if (favoriteOnly.value) query.favorite = 'true'
     if (page.value > 1) query.page = String(page.value)
     router.replace({ path: '/materials', query })
   }
   ```
   > **不要 `watch(route.query)`**。`replace` 只改 query 不重挂组件，若再监听 query 去 `load()`，会和 `search()` 形成双触发甚至死循环。保持「用户操作 → 写 query + 请求」单向。

3. 详情页返回改为「回到来处」：
   ```ts
   function goBack() {
     if (window.history.state?.back) router.back()
     else router.push('/materials')
   }
   ```
   ```vue
   <a href="#" class="back-link" @click.prevent="goBack">← 返回资料</a>
   ```
   > 不能直接用 `router.back()`：用户在详情页直接刷新或从分享链接进入时，`back` 会跳出站外。`history.state.back` 判断可覆盖这个边界。

`TasksView` 同理，但只需同步 `status` 与 `page`。

**影响面**

- 纯前端。会让列表 URL 变长，但可刷新保持、可分享，答辩演示时更好讲。
- 8 个 web 测试里没有对列表初始 query 的断言，风险低。

### P5 任务列表不会自动刷新

**现状**

`TasksView.vue` 只有手动「刷新」按钮，无定时器。而 `TaskDetailView.vue:73` 已经有一套成熟轮询：

```ts
onMounted(() => { load(); timer = setInterval(() => { if (task.value && ['QUEUED', 'RUNNING'].includes(task.value.status)) load() }, 3000) })
```

**为什么不符合使用**

AI 整理实测约 6 秒到 `WAIT_CONFIRM`。用户提交后进任务列表，看到「排队中」就一直不动，会怀疑任务卡死，反复点刷新。

**改法**

照 `TaskDetailView` 的模式，但**只在存在活动任务时才轮询**，避免空转：

```ts
import { onMounted, onUnmounted } from 'vue'
const activeStatuses = ['QUEUED', 'RUNNING']
let timer: ReturnType<typeof setInterval> | undefined

onMounted(() => {
  load()
  timer = setInterval(() => {
    const hasActive = results.value?.items.some(t => activeStatuses.includes(t.status))
    if (hasActive && !loading.value) load()
  }, 4000)
})
onUnmounted(() => { if (timer) clearInterval(timer) })
```

> 三点注意：
> 1. `load()` 开头已有 `if (loading.value) return`，天然防重入，无需额外加锁。
> 2. `load()` 不会把 `results` 置空，轮询时不会闪骨架屏。
> 3. 不轮询 `WAIT_CONFIRM` —— 那是等用户操作的终态，轮询无意义。

可选：在列表顶部加一行「有任务进行中，每 4 秒自动刷新」提示，让用户知道系统在动。

**影响面**

- 纯前端，仅 `TasksView.vue`。
- 轮询会让后端每 4 秒收到一次列表请求；单用户场景可忽略。若担心，可只在页面 `visibilityState === 'visible'` 时轮询。

### P6 受限资料按钮置灰但不解释原因

**现状**

`MaterialDetailView.vue:148`：
```vue
<el-button v-if="material.accessState === 'RESTRICTED'" disabled>AI 整理已限制</el-button>
```

用户在资料被改版后（P2 的连带行为）会看到这个灰按钮，页面顶部只有一个「AI 整理受限」标签，**没有任何文字说明为什么、怎么解除**。解除入口 `OwnerMaterialReview` 在页面最底部，需要滚动很久才能看到。

**改法**

1. 按钮包 tooltip —— **disabled 的按钮不触发鼠标事件，必须外包一层 `span`**：
   ```vue
   <el-tooltip v-if="material.accessState === 'RESTRICTED'" placement="top"
     content="资料内容已变更，需重新送审通过后才能使用 AI 整理">
     <span class="restricted-tip"><el-button disabled>AI 整理已限制</el-button></span>
   </el-tooltip>
   <el-button v-else type="primary" @click="router.push(`/materials/${material.id}/organize`)">提交整理任务</el-button>
   ```

2. 操作区下方补一条带跳转的提示：
   ```vue
   <el-alert v-if="material.accessState === 'RESTRICTED'" type="warning" show-icon :closable="false">
     <template #title>
       资料已变更，AI 整理被暂停。请到页面底部「资料审核」重新送审，通过后自动恢复。
       <el-button link type="primary" @click="scrollToReview">去送审</el-button>
     </template>
   </el-alert>
   ```
   ```ts
   function scrollToReview() {
     document.getElementById('owner-review-heading')?.scrollIntoView({ behavior: 'smooth', block: 'start' })
   }
   ```
   （`OwnerMaterialReview.vue` 已有 `aria-labelledby="owner-review-heading"`，可直接复用。）

3. **补前端路由守卫**。现在手输 `/materials/{id}/organize` 仍能进 `TaskCreateView`，用户能填完整张表单，提交时才被后端拒绝——白填一遍。在 `TaskCreateView` 的 `load()` 末尾加：
   ```ts
   if (material.value.accessState === 'RESTRICTED') {
     error.value = '这份资料已变更，需重新送审通过后才能发起整理'
   }
   ```
   并让提交按钮在 `error` 存在时禁用。

**影响面**

- 纯前端，2 个文件。
- 后端本来就是拒绝的，这里只是把失败提前到用户开始填表之前。

## 四、⚠️ 先决策：P2 会触发一个用户无法理解的后果

这是审查中发现的**后端既有行为**，不是本次新引入的问题，但 P2 一旦加上编辑入口就会立刻暴露出来。

**证据**

`MaterialServiceImpl.patch():212-215`：

```java
int changed = materials.updateConditional(materialId, userId, patch.getVersion(), title.trim(),
    subject, noteText, summary, status, now);
if (changed == 0) throw failedVersion(userId, materialId);
reviews.supersedeByMaterial(userId, materialId, now);   // ← 无条件调用
```

**只要调用 PATCH，无论改的是什么字段**，都会把该资料所有未失效的审核单置为 `SUPERSEDED`，并把 `access_state` 改为 `RESTRICTED`。

**后果**：用户给一份已审核通过的 PDF 改个标题（甚至只是补个标签），立刻失去 AI 整理能力，必须重新送审。用户会觉得「我只是改了个名字，怎么就不能用了」。

**两个选项**

| 选项 | 做法 | 代价 | 答辩可讲性 |
|---|---|---|---|
| **A. 接受现状** | 前端弹窗顶部加红字警示「修改标题、学科或标签会使当前审核失效」 | 0 后端改动，30 分钟 | 差。被问「为什么改标题要重新审核」时很难自圆其说 |
| **B. 区分内容与元数据**（推荐） | 只有正文/摘要变化才失效，元数据变更不失效 | 后端 1 处改动 + 1 条测试 | 好。审核绑定的是「内容」，不是「标题」，逻辑自洽 |

**B 的实现**

`MaterialServiceImpl.patch()` 第 215 行改为：

```java
boolean contentChanged = !Objects.equals(noteText, current.getNoteText())
    || !Objects.equals(summary, current.getSummary());
if (contentChanged) reviews.supersedeByMaterial(userId, materialId, now);
```

- `current` 是 `findOwnedForUpdate()` 读出的**更新前快照**，MyBatis 的 `updateConditional` 不会修改内存对象，所以比较有效。
- `delete()` 里的 `supersedeByMaterial` **保留**——资料被删了，审核当然失效。
- 需要补一条测试：PATCH 只改 `title` → `content_review.status` 保持 `APPROVED`、`access_state` 保持 `NORMAL`；PATCH 改 `noteText` → 变为 `SUPERSEDED` + `RESTRICTED`。

**建议**：如果时间允许选 B。这是把「审核失效」从「任何修改都失效」收敛到「内容变更才失效」，是一个能在论文里写清楚的规则收紧，而不是补丁。

## 五、可选改

### P7 删除用原生 `window.confirm`

`MaterialDetailView.vue:90`：
```ts
if (!window.confirm('确定删除这份资料？删除后将无法在资料列表中查看。')) return
```

**两个问题**：样式与全站 Element Plus 割裂；文案没说明「资料下的卡片会保留」——而这是删除时用户最关心的事（软删除不会级联删卡片）。

```ts
import { ElMessageBox } from 'element-plus'

try {
  await ElMessageBox.confirm(
    '删除后这份资料将从列表中移除，由它生成的卡片会保留。此操作不可撤销。',
    '删除资料',
    { type: 'warning', confirmButtonText: '确认删除', cancelButtonText: '取消',
      confirmButtonClass: 'el-button--danger' },
  )
} catch { return }   // 用户取消时 ElMessageBox 抛 'cancel'
```

> 必须 `try/catch` 并直接 `return`，否则用户点取消会变成未捕获的 Promise rejection。

### P9 分页越界不归位

`MaterialsView.vue:120` 的空态只在 `results.items.length === 0` 时出现，文案是「这里还没有符合条件的资料 / 写下第一条笔记」。但如果用户在第 3 页删掉最后一页的全部资料，`page` 仍停在 3，后端返回空页，页面就显示「写下第一条笔记」——而用户其实有几十份资料。这是**误导性空态**。

对比 `NotificationsView.vue` 已有正确处理（`page > 1 ? '本页暂无通知，请返回上一页查看。' : ...`）。

**改法**（在 `load()` 成功分支里）

```ts
results.value = await api<Page<Material>>(`/materials?${query}`)
// 页码越界：自动回退到最后一页
if (results.value.items.length === 0 && page.value > 1 && results.value.total > 0) {
  page.value = Math.max(1, Math.ceil(results.value.total / pageSize))
  loading.value = false
  return load()
}
```

同时把空态文案按 `page > 1` 分情况，与通知页保持一致。
