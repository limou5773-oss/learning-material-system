# 验收、启动部署与演示指南

适用日期：2026年10月27日。当前交付到D23，D24分为自动验收工具和仍需真实环境的最终验收。范围、缺口见[验收矩阵](验收矩阵.md)。本文中的命令和演示使用自编软件测试资料，不能充当真实AI效果评价。

## 1 运行依赖与配置

需要JDK 21、Maven 3.9+、MySQL 8.0、Node.js 24。先在项目根目录核对：

```powershell
java -version
mvn -version
mysql --version
node --version
npm --version
```

源码版本见`git rev-parse HEAD`。不要在报告或截图中输出完整环境变量、连接密码或令牌。仓库的`.env.example`只是配置示例，Spring Boot不会自动加载根目录`.env`，在启动进程的终端设置环境变量。数据库和上传文件不随Git同步。

## 2 一条命令自动验收

先创建**独立测试库**，不指向开发或生产库。现有集成测试会创建/删除测试记录并操作约束，测试库不能存个人资料。数据库名须为`learning_material_auth_test`或以下划线连接的后缀，例如`learning_material_auth_test_d24`。

```powershell
mysql -u root -p -e "CREATE DATABASE learning_material_auth_test_d24 CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;"
$env:DB_URL = 'jdbc:mysql://127.0.0.1:3306/learning_material_auth_test_d24?connectionTimeZone=UTC&forceConnectionTimeZoneToSession=true'
$env:DB_USERNAME = '你的专用测试库账号'
$testPassword = Read-Host '测试库密码' -AsSecureString
$env:DB_PASSWORD = [System.Net.NetworkCredential]::new('', $testPassword).Password
try {
    node scripts/verify.mjs
    if ($LASTEXITCODE -ne 0) { throw '自动验收未通过，查看本次输出目录' }
} finally {
    Remove-Item Env:DB_PASSWORD -ErrorAction SilentlyContinue
    $testPassword = $null
}
```

建库仅首次执行，已存在时直接配置，不需要删库重建。验收URL只接受上述`connectionTimeZone`和`forceConnectionTimeZoneToSession`查询选项，不接受可覆盖数据库名的其他连接参数；脚本同时固定测试进程的数据源连接及Flyway连接，防止继承的部署配置把迁移或测试导向其他库。脚本不创建、删除数据库，也不安装JDK/MySQL/Maven；缺少环境时明确失败。环境变量仅对子进程有效，不会保存密码到项目。

执行顺序：锁文件依赖安装`npm --prefix web ci` → `node --test tests/*.test.js` → `mvn -f backend/pom.xml clean verify` → `npm --prefix web run build`。脚本对子进程关闭真实OCR/模型及默认任务调度、管理员初始化，测试内部显式开启的本地模拟服务按各测试定义执行。不会修改当前终端的厂商配置。

每次输出独立目录`acceptance-output/`，保留阶段日志和JSON摘要，目录已忽略。非零退出、没有新测试报告、有失败/错误/跳过均不算通过；后续阶段显示未运行。自动通过只代表本次软件检查通过，摘要保留真实厂商、原生微信及人工评价待办，不代表P0/P1最终验收完成。日志只留本机，分享前检查是否含个人路径或测试数据。

## 3 本机启动与模拟演示

自动验收结束后，在新的终端重新配置开发库，避免将开发服务连接到验收库。首次开发库配置见[README](../README.md#在windows上运行)。

```powershell
$env:DB_URL = 'jdbc:mysql://127.0.0.1:3306/learning_material_dev?connectionTimeZone=UTC&forceConnectionTimeZoneToSession=true'
$env:DB_USERNAME = '你的开发库账号'
$devPassword = Read-Host '开发库密码' -AsSecureString
$env:DB_PASSWORD = [System.Net.NetworkCredential]::new('', $devPassword).Password
$env:STORAGE_ROOT = 'D:\LearningMaterialFiles'
$env:TASK_WORKER_ENABLED = 'true'
$env:TASK_PROCESSOR_MODE = 'mock'
$env:OCR_ENABLED = 'false'
$env:ADMIN_BOOTSTRAP_ENABLED = 'false'
mvn -f backend/pom.xml spring-boot:run
```

另开终端运行`npm --prefix web ci`、`npm --prefix web run dev`，打开`http://127.0.0.1:5173`。健康检查：`curl.exe -i http://127.0.0.1:8080/actuator/health`，预期200/UP。首次启动自动迁移V1—V17，不能导入拟议SQL覆盖迁移。停止后清除密码环境变量。管理员只按[初始化指南](管理员初始化与用户管理.md)显式首次创建，初始化后关闭开关；普通注册不会获得管理权限。

按以下顺序演示，页面措辞以当前界面为准：

1. 注册自己的演示账号并登录，新建文字笔记“软件验收：栈与队列”，正文写明“栈先进后出；队列先进先出。这是自编软件验收文本。”保存后在列表和详情查阅。
2. 从笔记提交“生成复习卡片”任务，阅读外部处理说明并选择同意。此演示后端为mock且OCR关闭，不调用厂商；候选必须显示模拟生成。
3. 打开整理任务与通知，查看待确认消息、执行步骤、候选摘要和来源。步骤记录可观察动作，不是模型隐藏思维。
4. 编辑一张候选卡片，选择保存，确认后进入知识卡片查阅来源。Web令牌目前只保存在内存，整页刷新需要重新登录；登录后应返回原路由并能读取已保存内容。未确认的候选不能算正式卡片。
5. 人工新建第二张卡片，体验收藏、搜索、布局/层级及手动关联；关系说明与两端来源可查。超过图查询上限需筛选，不能声称图谱无限加载。
6. 用第二个普通账号尝试读取第一个账号的资料，应被拒绝；用普通账号访问管理路由应显示无权限。
7. 如已有显式初始化的管理员，由本人主动送审一份自编资料，管理员填写理由查看/处置。统计大屏显示本库实际事件，未知费用不会变成零；mock本来就没有真实厂商账单。
8. 在微信开发者工具导入`miniprogram/`，用同一账号读取该笔记与卡片并编辑，Web刷新查验；两端持有旧版本时后保存返回冲突。此步骤必须在真实工具中执行后才能记录原生通过，Node Page测试不替代。

## 4 jar与Web静态资源部署

这是可执行的部署说明，尚无本轮公网部署结果。服务端配置沿用环境变量；数据库、文件目录、HTTPS证书由部署者在目标主机提供。Spring Boot支持环境变量和命令行外部配置，见[官方说明](https://docs.spring.io/spring-boot/reference/features/external-config.html)。

```powershell
# 先按第2节通过测试；构建产物由clean verify生成
java -jar backend/target/backend-0.1.0-SNAPSHOT.jar --server.address=127.0.0.1
```

后台进程由目标主机的服务管理器托管，工作目录和`STORAGE_ROOT`指向持久化位置。备份MySQL与文件目录须对应同一业务时间点；升级前备份并在独立库恢复核对，Flyway迁移失败应保留错误处理，不能跳过校验写成部署成功。回退旧jar前确认其是否兼容已经迁移的表结构。

`npm --prefix web run build`生成`web/dist/`，部署到静态Web服务器。Vite开发服务器和`vite preview`只用于本机开发/预览，不能作为生产托管方案，见[Vite官方部署指南](https://vite.dev/guide/static-deploy.html)。前端API使用`/api/v1`相对路径，生产采用同源HTTPS反向代理；SPA刷新路由需回退到`index.html`。

以下是Nginx HTTPS虚拟主机内的配置片段，域名、证书和静态目录按目标主机配置；不是已经部署的地址。`proxy_pass`不带URI尾部，保留原`/api/v1`路径，依据[Nginx官方文档](https://nginx.org/en/docs/http/ngx_http_proxy_module.html#proxy_pass)。

```nginx
root /srv/learning-material-system/web/dist;
index index.html;
client_max_body_size 34m;

location /api/ {
    proxy_pass http://127.0.0.1:8080;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_read_timeout 60s;
}
location / {
    try_files $uri $uri/ /index.html;
}
```

上传上限同时受反向代理、Spring multipart及业务文件校验限制。不要把上传目录、日志或数据库备份放到Web静态根目录。发布小程序前将`miniprogram/config.js`请求基址改为实际HTTPS域名，并配置request、uploadFile、downloadFile合法域名；手机的127.0.0.1不能访问电脑后端。真实微信绑定/登录接口尚未实现，目前只能账号密码同账户登录。

## 5 真实厂商与论文证据补录

依据[腾讯云OCR配置](OCR接入配置.md)与[DeepSeek配置](DeepSeek接入配置.md)，在本机安全配置凭证后分别运行model与agent模式；不要把密钥粘贴到聊天或仓库。至少保存文字PDF、图片、混合或失败样本的真实任务及人工确认记录，观察受限规划工具选择、失败后的调整或明确结束。不预设智能体比固定流程更好。

每个真实评价样本记录：样本编号、合法来源/授权、采集日期、类型/页数/清晰度；提交与结束时间、目标、实际处理范围；厂商、模型标识、模式、提示版本、步骤、请求标识、调用数、token；厂商实际费用及币种或“未提供”；摘要事实一致性、要点覆盖、来源引用有效性和关联合理性及评价人。固定流程与智能体对照使用同样样本、模型和预算，并说明差异。先确定人工评分规则，再采集结果，不从平台任务完成率推算输出质量。

将原始私有样本和完整厂商响应留在受控本机目录，仓库只保留脱敏且有使用权的证据。当前尚无该轮真实效果数据，不填写虚构准确率、耗时、成本或学习成绩改善结论。论文引用的软件结构、页面与自动化结果可来自对应实际代码和证据；效果结论必须等真实样本测量完成。参考文献另行逐项核验，测试输出不是参考文献。
