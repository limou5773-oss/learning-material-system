# 个人学习资料智能整理系统数据库设计

版本V1.0，2026年10月22日。依据开题报告整理的开发建议，共18张拟议表。其中`app_user`、`auth_session`、`material`、`tag`和`material_tag`已分别通过V1至V3受控迁移实现，`favorite`的资料收藏部分通过V4迁移实现，`ai_task`与`ai_tool_call`通过V5迁移实现。其余拟议表未执行。此处字段与《拟议建表.sql》由同一结构来源生成。业务规则以《需求与开发说明书.md》为准。

通用字段：id为BIGINT自增主键；created_at和updated_at为DATETIME，约定保存UTC。所有ID在API中序列化为字符串，JSON时间带Z。通用字段不在各表重复列出。

索引中的外键只约束引用存在；所有者一致性、关系方向、层级无环、版本冲突、任务状态及幂等摘要必须在服务层验证。没有ON DELETE CASCADE，删除采用业务逻辑状态。

D10领取时在短事务内锁定可领取行，`execution_epoch`递增并写入30秒租约；心跳每10秒续租。恢复过期任务时，旧轮次未完成的调用标为`UNKNOWN`，不会据此推断外部费用为零。步骤和上下文写入均需匹配当前epoch、RUNNING状态及有效租约；取消后清空租约并拒绝迟到写入。重试生成新任务并保留`parent_task_id`。

## 19 事务与数据生命周期

任务提交、候选确认、用户停用、审核处置分别建立短事务。外部OCR和模型请求不能处于数据库持锁事务中。确认操作锁定任务与源资料，保证卡片、来源、所选关系、正式摘要、标签及最终状态整体提交。

资料逻辑删除后片段只用于受控历史一致性，不允许通过卡片来源重新读到已删除原文。正式卡片可以保留来源失效提示，此时CardSource的quoteText与content都返回null。布局、收藏和图查询过滤已删除卡片。管理员受控查看资料必须记录CONTENT_VIEW。

ai_task.config_json保存本次页段、预算、输入快照、模型和OCR标识及同意时间。material_chunk按版本缓存；worker写入必须在持有task行锁并验证epoch的短事务内完成，防止过期执行者修改片段或结果。

card_source对每张卡片与片段只保留一条来源记录，多个摘录可合并quote_text；offset以Unicode码点计数，空时仅使用片段引用。RELATED关系按ID规范化；PREREQUISITE表示起点为终点的前置知识，EXAMPLE表示起点为终点的示例。

所有NOT NULL字段由应用明确赋值。SQL仅包含时间默认值，不将配置中的枚举和初始版本隐藏为数据库隐式行为。Flyway等迁移工具在初始化时选定并锁定版本，按用户笔记、文件、任务、卡片、管理等开发阶段分批建表。
