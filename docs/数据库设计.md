# 个人学习资料智能整理系统数据库设计

设计基线V1.0，2026年10月22日；实现说明更新于2026年10月27日。依据开题报告整理的开发建议，共18张拟议表。`app_user`、`auth_session`、`material`、`tag`和`material_tag`通过V1至V3迁移实现，`favorite`的资料收藏部分通过V4实现，`ai_task`与`ai_tool_call`通过V5实现，`material_chunk`与`ai_result`通过V6实现，`knowledge_card`、`card_source`与`card_relation`通过V7实现，`card_layout`通过V13实现，`notification`通过V14实现，`review_record`用户状态审计部分通过V15实现，V16实现`content_review`、审核访问/决定审计及审核通知。其余拟议表未执行。下表保留设计基线，实际DDL以`backend/src/main/resources/db/migration/`为准；历史拟议SQL已移除；当前完整初始化SQL仅用于首次空库，已有业务库只执行对应增量SQL。业务规则以《需求与开发说明书.md》为准。

D12时的V7仅支持从任务确认生成卡片：`task_id`、`candidate_key`、`tags_json`为非空，正文为TEXT；`generation_mode`单独保存MOCK标识，避免将模拟结果混作真实模型输出。卡片来源的引用与起止位置均非空，唯一键为`(card_id,chunk_id,start_offset,end_offset)`，允许同片段不同摘录。关系增加`origin=USER_CONFIRMED`。D17的V12补充人工卡片，D19补充三类已确认关系及限量图查询。

D13的V8增加基线之外的`pdf_page_cache`支持表。`material_chunk.extraction_method`扩展为PDF_TEXT，`page_no`保存实际页码；旧NOTE及METADATA片段保持不变，历史引用不会重新生成或覆盖。

通用字段：id为BIGINT自增主键；created_at和updated_at为DATETIME，约定保存UTC。所有ID在API中序列化为字符串，JSON时间带Z。通用字段不在各表重复列出。

索引中的外键只约束引用存在；所有者一致性、关系方向、层级无环、版本冲突、任务状态及幂等摘要必须在服务层验证。正常资料/账号操作采用业务逻辑状态；V14通知在硬删任务时按联合外键级联清理，审计用户外键仍限制硬删，不以级联代替日常业务删除。

## 17 content_review 内容审核队列

V16实际实现，只有用户主动送审USER_SUBMITTED，没有自动规则扫描。送审必须携带页面资料version并锁行核对，唯一版本只允许一条；旧PENDING记录保留但isCurrent=false且不能访问/处置。

| 字段 | 类型 | 可空 | 含义 |
| --- | --- | --- | --- |
| material_id / user_id | BIGINT | 否 | 送审资料及本人，组合外键保证一致 |
| material_version | INT | 否 | 获授权的资料内容版本 |
| title / material_type | VARCHAR(255) / VARCHAR(16) | 否 | 送审快照，列表不泄露修改后标题 |
| trigger_type / access_scope | VARCHAR(32) | 否 | USER_SUBMITTED / MATERIAL_CONTENT |
| reason | VARCHAR(1000) | 否 | 本人送审原因，trim保存 |
| status / version | VARCHAR(16) / INT | 否 | PENDING、APPROVED、REJECTED及审核乐观版本 |
| decision_reason | VARCHAR(1000) | 是 | 管理员处置原因 |
| created_at / decided_at | DATETIME(6) | 否 / 是 | UTC送审及处置时间 |

## 20 事务与数据生命周期

任务提交、候选确认、用户停用、审核处置分别建立短事务。外部OCR和模型请求不能处于数据库持锁事务中。确认操作锁定任务与源资料，保证卡片、来源、所选关系、正式摘要、标签及最终状态整体提交。

资料逻辑删除后片段只用于受控历史一致性，不允许通过卡片来源重新读到已删除原文。正式卡片可以保留来源失效提示，此时CardSource的quoteText与content都返回null。布局、收藏和图查询过滤已删除卡片。管理员受控查看资料必须记录CONTENT_VIEW。

ai_task.config_json保存本次页段、预算、输入快照、模型和OCR标识及同意时间。material_chunk按版本缓存；worker写入必须在持有task行锁并验证epoch的短事务内完成，防止过期执行者修改片段或结果。

实际V7的card_source按卡片、片段和摘录区间去重，同片段可有不同摘录。offset沿用D11的Java字符串UTF-16代码单元计数，起始包含、结束不包含；例如辅助平面字符占两个代码单元。服务端校验引用等于该区间原文，并限制为原候选允许的固定版本片段。RELATED关系按较小ID为起点规范化，反向重复在写入前拒绝；PREREQUISITE表示起点为终点的前置知识，EXAMPLE表示起点为终点的示例。来源被删除或受限时，读取接口将quote_text和片段正文置空，附不可用原因。

所有NOT NULL字段由应用明确赋值。SQL仅包含时间默认值，不将配置中的枚举和初始版本隐藏为数据库隐式行为。Flyway等迁移工具在初始化时选定并锁定版本，按用户笔记、文件、任务、卡片、管理等开发阶段分批建表。
