# JWT 登录说明

2026-10-29。Web、微信小程序的账号密码登录和已绑定微信登录统一使用 HS256 签名 JWT。接口仍返回 `accessToken`、`tokenType: Bearer`、`expiresAt` 和 `user`，客户端继续发送 `Authorization: Bearer <accessToken>`。

## 本机配置

直接修改原 `backend/src/main/resources/application.yml` 的 `lms.jwt`，不新增环境变量或本机配置文件：

| 字段 | 用途 |
| --- | --- |
| `secret` | 至少 32 个随机字节的 Base64 编码；本机已生成，不输出到聊天或日志 |
| `issuer` | 签发方，默认 `learning-material-system` |
| `ttl` | 固定有效期，默认 `7d`，可写 `12h` 等 Spring Boot 时间长度，至少 1 秒 |

修改配置后重启后端。签名密钥不能上传 GitHub；自动测试中的公开密钥仅供测试使用。密钥缺失、格式不正确或强度不足时启动报错，不自动使用默认弱密钥。

## 签发和认证

JWT 包含 `iss`、`sub`（用户 ID）、`jti`（唯一 ID）、`iat` 与 `exp`。不放密码、微信身份或第三方密钥，角色从数据库中的当前账号记录读取。签名不等于加密，客户端不应将解码出的字段作为可信权限依据。

后端先验证 HS256 签名、签发方和过期时间；不接受无签名令牌或其他签名算法。通过后，用完整 JWT 的 SHA-256 摘要查找尚未撤销且未过期的 `auth_session`，核对所属用户并检查账号状态。数据库故障继续报错，不伪装为认证成功。

保留会话表以支持立即撤销：退出只撤销当前会话，修改密码或停用账号撤销该账号全部会话，微信解绑只撤销小程序会话。账号重新启用后，已撤销的 JWT 也不会恢复。

## 切换与验证范围

无需修改或重新导入数据库表。重启后端、重新编译小程序后，两端均需重新登录，旧随机令牌失效。已有用户、资料和密码不改动。Web 仍只在页面内存保存令牌，刷新后需登录；小程序保存令牌的格式检查已改为三段 Base64URL，沿用原本的本地存储与 401 清理逻辑。本轮没有新增刷新令牌。

实现采用 [JJWT 0.13.0 官方文档](https://github.com/jwtk/jjwt/blob/0.13.0/README.adoc)中的签发与签名验证 API。后端 JWT、配置绑定与账号操作15项检查，小程序登录与账号12项检查通过；未连接业务数据库运行验收，也未进行全项目回归。
