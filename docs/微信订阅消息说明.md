# 微信订阅消息当前范围

更新日期：2026年10月26日。D20已确认需求将站内通知作为必做项，微信订阅消息作为取决于账号能力、用户授权和模板的附加渠道。

当前系统使用统一账号密码登录，尚未接通真实微信身份绑定；没有已验证的订阅授权记录、可用消息模板或真实微信发送凭证。因此D20只生成站内通知，channelStatus固定为NOT_REQUESTED，页面显示“微信订阅消息尚未开通，站内通知正常”。不调用微信发送接口、不申请用户授权，不将未请求伪装为发送成功或失败。

任务进入WAIT_CONFIRM或FAILED时，站内通知与任务状态在同一短事务中保存，并按任务及状态事件去重。通知中心可查看、筛选未读、切换已读状态和跳转本人任务详情。此功能不依赖微信渠道；当前渠道尚未发送，因此没有微信失败隔离、重试、送达率或计费的实测证据。

后续接通真实微信订阅渠道前，需要准备：

1. 小程序实际账号及其可用接口能力；真实微信登录与统一用户的绑定，openid由服务端验证，不能信任客户端任意提交。
2. 该账号后台可用的订阅消息模板、字段规则及业务跳转页，使用自编资料验证，无敏感笔记正文或密钥进入消息。
3. 用户在真实小程序中明确同意的订阅授权；未授权时保持NOT_REQUESTED，站内消息继续可用。
4. 本机或部署环境的凭证配置，通过受控环境变量/秘密存储管理，不在聊天、源码或GitHub提交。
5. 以真实联调时的微信官方开发文档和账号后台核对参数。发送放在站内事务提交之后异步执行；失败只更新渠道状态，不回滚站内消息或任务结果。仅对明确可恢复的瞬时错误有限重试，鉴权、权限和确定性参数错误直接报告。

以上是后续接入条件，不表示D20已经实现微信发送适配器。微信开发者工具原生编译和真机订阅验证仍按用户此前选择暂缓。站内通知的自动化、HTTP和浏览器证据见[D20记录](../tasks/evidence/D20.md)。
