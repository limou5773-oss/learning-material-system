# 个人学习资料智能整理系统需求与开发说明书

项目名称：面向Web与微信小程序的个人学习资料智能整理系统设计与实现

版本：V1.0 开发建议稿　编写日期：2026年10月22日

本文将开题报告转化为可分阶段实施的软件需求和开发约定，供本人及后续开发协作者使用。D01、D02已实现并分别留有验证记录；其余接口、表结构、限制值和验收条件仍为拟议方案，不代表已运行或已测试。开发从登录、资料上传和双端查阅开始，逐步完成智能整理、知识展示与后台管理。

## 2 用户角色与权限

### 2.1 普通用户

普通用户管理本人的资料、标签、任务、候选结果、卡片、卡片关联、布局、收藏与通知。所有读取、编辑、下载、工具调用和搜索都由服务端根据当前登录用户限定数据归属。客户端提交的userId、openid或文件路径不能作为授权依据。

### 2.2 管理员

管理员维护用户启停状态，检查资料元数据、失败任务和调用统计，处理进入审核队列的资料。后台列表默认只展示标题、类型、归属、时间和审核状态；查看正文需要存在待审核记录并写入访问审计。普通管理权限不等同于任意读取私人笔记。

用户不能自行设置管理员角色。首个管理员通过初始化时的明确配置创建，密码通过环境变量或交互输入设置，不提供写死的默认管理密码。管理员停用用户后，应立即使其已有会话失效。

### 2.3 权限矩阵

| 操作 | 本人 | 其他普通用户 | 管理员 |
| --- | --- | --- | --- |
| 查看及修改私人资料 | 允许 | 禁止 | 仅授权审核正文可查看 |
| 提交AI任务和确认结果 | 允许 | 禁止 | 不代替用户确认 |
| 下载原文件 | 允许 | 禁止 | 经审核授权且留痕 |
| 修改卡片和布局 | 允许 | 禁止 | 禁止代改 |
| 查看平台聚合指标 | 禁止 | 禁止 | 允许 |
| 用户启停和审核处置 | 禁止 | 禁止 | 允许并留痕 |

## 3 业务流程与页面

### 3.1 资料采集与双端查阅

用户在小程序拍照或选图上传，或录入文字笔记，填写标题、学科和初始标签。Web端通过同一账户读取资料，完成筛选、原文查阅与整理。Web上传PDF采用前端批量排队、单文件请求的方式，单个文件失败不使其他文件回滚。

上传成功只表示资料已保存。界面应分别显示“已上传”和AI任务状态，用户选择目标后才提交整理任务，以便明确外部AI处理范围。相同用户上传相同文件时给出重复提醒，允许复用已有资料或明确选择继续保存，不跨用户提示是否存在相同文件。

### 3.2 智能整理与确认

用户选择资料及整理目标，查看所选页段和外部服务处理说明后提交。服务端将任务加入队列，智能体根据资料类型规划步骤，调用允许的工具。用户可以查看阶段、工具名称、执行结果摘要和异常信息。

执行成功先进入待确认状态，界面并排展示原文与候选摘要、标签、卡片及关联。用户可以删改候选内容、取消不合理关联，再确认保存。正式知识卡片只能通过明确的保存接口产生，模型无权直接写入或删除正式内容。

### 3.4 小程序页面清单

底部导航建议为“资料”“采集”“卡片”“我的”。资料页含搜索和学科筛选；采集页提供拍照、选图及文字记录；资料详情支持原文或文字查看、目标选择和任务入口；任务页展示状态及候选结果；卡片页支持查看、收藏、搜索和简单文字编辑；“我的”包含通知、绑定和退出。

小程序无需复制Web的拖拽画布和统计大屏。候选确认在小程序中采用分步表单，以查看、删改和确认文本卡片为主；来源定位优先显示图片或页码与引用文本。

所有列表都必须具有加载、无数据、请求失败和重试状态；上传必须显示进度及单文件错误；按钮提交中禁止重复点击，但服务端仍需保证幂等。

## 4 功能需求与验收标准

### 4.1 账户与协同

F01 账户登录及个人信息。P0。Web提供注册、密码登录与退出，小程序先以同一账号登录。密码经过服务端校验并使用自适应密码散列存储。验收时新账号可以登录两端，退出后原令牌不能继续调用受保护接口；未登录访问返回401。

F02 微信绑定。P0在本地提供清楚标注的开发模拟，P1接入真实微信登录。用户先登录已有账号，在小程序取得临时登录code并提交服务端完成绑定；以后可用微信登录同一账号。已有绑定发生冲突返回409，不自动合并账号，不凭客户端openid绑定。解除绑定需再次验证账号密码，解绑不删除学习资料。真实验收需使用可用AppID和设备或开发者工具记录。

F03 双端一致性。P0。两端使用统一用户标识与API，编辑资料和卡片时携带version。版本冲突返回409和当前版本，保留客户端未保存内容，并提示重新读取或人工合并。验收时双端先读取同一版本，先保存一端成功，另一端旧版本保存不能覆盖新内容。

### 4.2 资料管理

F04 图片采集。P0。支持JPEG、PNG图片，拍照或选图上传。后端核对扩展名、实际类型、大小与归属，生成受控storageKey。验收时有效图片可在Web与小程序读取，伪装类型和超限文件被拒绝，用户B无法通过猜测ID下载用户A的文件。

F05 PDF上传与预览。P0。Web一次选择多个PDF，分别上传并展示结果；详情支持授权预览和下载。密码加密、损坏或不支持解析的PDF仍需给出清晰状态，不将失败伪装为成功解析。重复上传通过服务端SHA-256摘要提示，文件名不能作为路径或唯一标识。

F06 文字笔记。P0。支持创建、查看、编辑及删除文字笔记，包含标题、学科、标签和正文。标题为空、内容超限时返回字段错误。编辑成功version递增；AI任务引用的历史版本文本保留在已生成片段中，不能被编辑覆盖。

F07 检索归档与收藏。P0。按标题和笔记正文关键词、学科、标签筛选本人资料，分页返回。归档与删除分别处理，归档资料仍可在归档筛选中查看，删除后不再可下载或提交AI。收藏采用幂等添加与删除，同一对象不会出现重复收藏。

F08 删除与来源失效。P1。删除资料前说明影响，取消其非终态任务并阻止新的确认保存。已有知识卡片可以保留，但来源显示“原资料已删除”，不再通过历史片段接口泄露原文。物理文件与片段清理由显式维护流程处理，不在删除请求中级联破坏历史卡片。

### 4.3 智能体与结果

F09 整理目标。P1。提供生成复习卡片、提炼课件重点、整理并关联已有笔记三类目标，允许补充说明。任务记录目标类型、说明、资料版本、页段、模型配置快照和外部处理同意时间。空目标或超限输入返回422。

F10 文本提取与OCR。P1。文字层PDF优先直接提取；图片和扫描页调用OCR，混合PDF按页判断。片段记录资料版本、片段号、页码及提取方式。OCR空结果或低质量提示反馈给智能体，超过预算时说明实际处理范围；不得把未识别或未处理页当成完整原文。

F11 受限智能体执行。P1。后端维护工具白名单和参数定义，模型根据目标提出下一步动作，工具反馈可影响后续选择。验收需要展示至少一例文字PDF、一例图片以及一例工具失败后的调整或明确结束记录，证明执行并非只有固定摘要请求。日志仅记录可观察动作，不采集或展示模型隐藏思维。

F12 候选内容校验。P1。候选结果必须符合结构，所有来源chunkId属于当前用户可访问的资料与固定版本；文本引用能在对应片段中匹配。格式或来源错误允许在预算内修复一次，仍不合格则失败并展示原因。来源校验只证明定位有效，不能宣称生成内容事实必然正确。

F13 人工确认。P1。用户选择要保存的卡片，修改摘要、标签和卡片正文，明确勾选关联建议。保存前再次校验任务状态、源资料版本、卡片归属和候选结构；一个事务写入结果、卡片、来源与所选关联并结束任务。重复请求返回同一保存结果，不能重复生成卡片。

F14 任务管理。P1。支持排队、执行、待确认、完成、失败和取消状态，显示当前阶段与安全的错误说明。取消后禁止后续结果写入；已发出的外部调用可能仍产生费用。失败重试创建新任务，保留parentTaskId和原始日志，不把旧任务改回排队。

### 4.4 知识组织与提醒

F15 知识卡片。P1。支持人工创建、AI确认创建、查看、编辑、收藏和按标题、正文、学科及标签搜索。AI来源记录保持可回看；用户编辑后的内容标记为已人工修改，不能继续显示为模型原始输出。卡片更新使用version校验。

F16 拖拽与思维导图。P1。Web支持拖拽卡片位置与顺序并恢复保存布局；层级关系用于生成思维导图。层级调整验证当前用户、父节点存在且不成环。布局使用layoutVersion进行整体条件保存，旧版本写入返回409，避免两浏览器静默覆盖。

F17 关联图。P1。展示本人卡片及已确认关联，点击关系查看说明与两端来源。初版关系类型限定RELATED、PREREQUISITE、EXAMPLE三个枚举，模型建议先进入候选结果。禁止自关联，禁止跨用户关系；同类型RELATED关系按较小ID作为source规范化，以避免正反向重复。

F18 通知。P1。在任务进入WAIT_CONFIRM、FAILED时生成站内通知；终态变化和审核处置也可产生对应消息。重复状态提交不重复产生同类通知。微信订阅消息是附加渠道，未授权、渠道失败或无模板都不影响站内消息与任务结果。

### 4.5 平台管理

F19 用户状态管理。P1。管理员查看必要的账号信息并启停用户，必须填写原因且保留操作记录。不得在管理接口返回passwordHash、令牌摘要、openid或AI密钥。

F20 敏感内容审核。P1。资料进入审核队列的依据为用户主动提交或已启用规则命中，不以“所有私人内容默认可读”实现。审核状态为PENDING、APPROVED、REJECTED，记录触发原因、授权范围、查看正文操作及处置理由。驳回后资料标记为RESTRICTED，禁止继续向AI发送；用户仍可查看自己的原文并修正，修正后主动重新送审。审核与资料删除状态分开存储。D22实现用户主动提交，未启用规则扫描；送审携带本人页面显示的version，并发编辑409。管理员正文、原文件及决定均限当前PENDING版本，查看需原因审计，文件和决定还需同会话已有正文查看记录。处置递增审核version，不递增资料内容version；驳回后本人仍可读原文件，PATCH修正新版本再送审。驳回取消未完成任务并阻止新尝试、重试和结果发布，已获准开始的外部请求不能撤回，其活动记录标UNKNOWN。处置、审计、任务取消和REVIEW_DECIDED站内通知同事务。

F21 任务与调用监控。P1。管理员查看脱敏任务目标类型、状态、工具名、耗时与错误码，默认不返回目标自由文本、提示词原文和个人片段。只允许用户本人重新提交业务任务；后台不隐式以用户身份调用模型。

F22 统计大屏。P1。展示当前有效资料数、按学科分布、上传趋势、AI实际调用尝试数、任务状态分布和任务完成率。零数据展示空状态；上游费用未知显示“未提供”。指标需对应后文统一口径，禁止填入演示用固定增长数字。

## 5 非功能需求与默认限制

以下数字为本项目初始配置建议，属于待验证的限制或目标，不是已测性能。后续根据电脑配置、接口额度及测试记录调整。

| 项目 | 初始约定 | 验证方式 |
| --- | --- | --- |
| 分页 | page从1开始，pageSize默认20，上限100 | 边界与越界请求 |
| 文件 | PDF不超过30 MiB，图片不超过10 MiB | 超限返回413 |
| PDF范围 | 上传后校验不超过100页；单次整理最多20页 | 页数与页段校验 |
| 批量上传 | 一次选择最多10个文件，同时上传2个 | 混合成功失败场景 |
| 文本 | 笔记正文最多20000字，目标补充最多1000字 | 前后端一致校验 |
| 任务 | 单用户最多2个排队或执行任务，worker初始2个 | 并发提交与429 |
| 智能体预算 | 最多8个动作步骤，模型尝试最多12次，OCR最多20页 | 达限明确失败或请求缩小范围 |
| 时间 | 单次外部请求超时60秒，任务执行总时限300秒 | 模拟慢响应 |
| 重试 | 仅瞬时网络错误、429和部分5xx有限重试，每逻辑调用最多2次重试 | 记录全部尝试，不重试权限错误 |
| 查询体验 | 单用户1000条资料、单客户端下列表P95目标小于1秒 | 记录环境、数据量与实测结果 |
| 结果可靠性 | 每张AI卡片至少一个有效来源，用户确认后才入库 | 自动校验与人工对照 |

任务总时限仅从worker开始执行时计算，排队时间单独显示。超长PDF由用户选择页段，不默认把前20页结果描述为全文摘要。若生成卡片过多或内容超过结构限制，要求模型压缩或用户缩小范围，不静默截断后保存。

## 6 技术方案与工程组织

### 6.1 已明确的技术栈

后端使用Spring Boot、MyBatis-Plus和MySQL，Web使用Vue3、Element Plus与ECharts，小程序使用原生微信小程序。采用一个后端进程提供统一API，文件存储与MySQL元数据分离。无需为本项目额外引入微服务、Neo4j、Python服务或模型训练平台。

### 6.2 开发建议选型

后端建议使用JDK 21、Spring Boot 3.5系列和Maven；初始化时锁定具体补丁版本。MyBatis-Plus使用与Boot 3匹配的mybatis-plus-spring-boot3-starter，并按官方说明选择分页插件依赖，不重复叠加原生MyBatis starter。密码校验和请求鉴权使用Spring Security；令牌为服务端生成的随机不透明会话令牌，MySQL保存其摘要，便于退出与禁用账号立即生效。

Web建议采用Vite、TypeScript、Vue Router和Pinia，使用依赖锁文件固定版本。拖拽编排优先使用有维护的Vue拖拽组件或小型交互实现，初始化时验证其版本兼容；不把ECharts画布当作卡片编辑器。PDF文字提取建议使用Apache PDFBox；OCR与模型分别通过OcrClient、LlmClient接口封装。

数据库先兼容本机现有MySQL 8.0环境，后续部署版本单独记录。开发文件存放到项目外配置目录，通过鉴权接口读取；生产可替换对象存储而不改变业务storageKey语义。异步队列使用MySQL任务表加定时扫描和有界线程池，初版不依赖Redis、消息中间件或SSE。

## 7 账户安全与双端协议

### 7.1 会话与绑定约定

注册时用户名限制为6至32位英文字母、数字或下划线，密码建议8至64位，服务端使用BCrypt并额外限制UTF-8编码长度不超过72字节。登录成功返回一次性可见的随机令牌，后续通过Authorization Bearer传递；数据库只存SHA-256令牌摘要。会话有效期建议7天固定期限，到期重新登录，不在日志中输出令牌。

Web初版将令牌保存在页面内存，需要刷新后重新登录；如后续启用浏览器持久会话，应单独设计HttpOnly Cookie与CSRF防护。小程序在本地受控存储令牌，退出清理。开发阶段可以使用明确标识的微信模拟适配器；生产配置不允许启用模拟身份。

绑定时服务端用code换取微信身份，appid来自服务端配置。用户不提交可信openid；未绑定微信登录返回WECHAT_BIND_REQUIRED并引导使用已有账号登录绑定。解除绑定只解除关系，不迁移数据。没有短信、邮箱找回能力时，不显示无法兑现的找回密码功能。

### 7.2 数据版本与读取

资料与卡片PATCH请求携带version，后端按id、userId、version进行条件更新，成功将version加1；影响行数为0时区分不存在与版本冲突。任务固定materialVersion，原文变更后待确认结果不能写成当前版本的成果。资料元数据、正文或标签变更均递增资料version，收藏和布局操作不改变内容version。

页面回到前台、保存成功后或手动刷新时重新读取服务端数据。任务排队或执行时建议每3秒轮询，进入待确认或终态后停止轮询。断网显示本地未提交内容和明确的待重试状态，初版不承诺离线自动同步。

### 8.2 必须落实的约束

所有表使用utf8mb4、InnoDB和BIGINT主键，统一created_at与updated_at。API中的所有ID使用十进制字符串，避免JavaScript大整数精度损失。时间在库内统一保存UTC，接口使用带Z的ISO 8601字符串，界面和统计按Asia/Shanghai显示。

账号名、微信绑定、用户标签名、任务请求键、候选卡片键和收藏必须有唯一约束。ai_task以user_id与request_key防止重复创建；knowledge_card以task_id与candidate_key防止重复落库；notification使用user_id与dedupe_key去重。外键仅保证引用存在，所有者一致性仍由服务端校验。

card_layout按用户与layout_key保存一份JSON坐标集及version，单次请求只写本人未删除卡片。收藏必须且只能关联一个资料或卡片；卡片层级不得成环。正文不做硬删除级联；普通删除走逻辑状态并执行来源不可访问规则。

### 8.3 摘要与来源的持久化

material.summary保存用户确认后的摘要，material_tag保存确认后的标签；确认时可以选择替换标签或与原标签合并，接口默认MERGE。候选摘要和候选标签保存在ai_result，不参与正式资料搜索或统计。来源片段一旦被正式卡片引用就不能原地覆盖。

确认保存将material.summary和标签合并写入，并递增资料version。成功任务仍保留输入materialVersion以供审计；重复确认直接返回已保存的cardIds和结果版本，不因当前资料版本已递增而误报失败。若另一个任务先确认或用户先编辑，当前待确认任务收到SOURCE_VERSION_CHANGED并要求基于新版本重新整理。

完整字段与索引见配套《数据库设计.md》。拟议SQL不包含演示账号、真实学习内容或任何API密钥，正式开发将按功能分批编写和验证迁移脚本。

## 9 API接口与数据契约

### 9.1 通用协议

接口前缀为/api/v1，JSON字段使用camelCase，枚举使用大写下划线。成功响应为包含data与requestId的对象，分页data包含items、page、pageSize、total。无数据列表返回空数组。错误响应包含error.code、error.message、可选字段错误及requestId；不返回堆栈、SQL或第三方完整响应。

状态码约定：400表示JSON或参数语法错误，401未登录，403没有功能权限，404不存在或不属于当前用户，409版本或状态冲突，413文件过大，415类型不支持，422业务字段校验失败，429配额或频率受限，500内部异常且仅返回安全说明，502外部服务异常，503暂不可用。资源归属失败统一404，避免泄露其他用户对象是否存在。

创建返回201，异步任务提交返回202，查询及修改返回200，成功删除或退出返回204且不带正文。分页按updatedAt与id倒序，排序字段使用白名单。外部API密钥只在服务端配置，不下发前端。

## 10 学习资料整理智能体

### 10.1 组成与边界

智能体由目标上下文、规划适配器、工具注册表、执行循环、预算器、结构校验器和任务记录组成。模型可以提出工具动作，具体执行由服务端完成；任意SQL、命令执行、外网地址访问和正式数据删除都不注册为工具。资料正文及OCR文本视为待处理数据，其中即使含有“忽略规则”等文字，也不能改变系统权限或工具集合。

模型支持原生工具调用时采用原生协议，否则采用经过JSON Schema校验的结构化动作协议；都必须通过同一个工具执行器。执行记录保存工具名、阶段、耗时和简短结果，不保存模型隐藏思维，也不向用户暴露完整系统提示或凭证。

### 10.2 工具定义

| 工具 | 参数范围 | 输出与限制 |
| --- | --- | --- |
| extract_pdf_text | 当前materialId、固定版本、所选页段 | 片段、页码、需OCR页，不访问任意路径 |
| recognize_image | 当前图片或所选扫描页ID | OCR片段、质量提示、实际处理页 |
| search_personal_materials | 关键词、可选学科、limit最多10 | 本人可访问片段或卡片，带版本 |
| generate_summary_cards | 已验证片段ID、目标、可选检索结果 | 候选摘要、标签、卡片、关系 |
| validate_candidate | 候选结构与来源引用 | 字段、来源、引用和归属校验结果 |

用户身份、租约标记及存储路径由服务端上下文注入，模型不能通过参数覆盖。关联检索初版采用标题、标签和文本关键词召回，模型根据召回证据判断候选关联并给出说明；不把基础实现称作已完成向量数据库或专业知识图谱。

D11模拟阶段由服务端固定调用`prepare_source(materialId,materialVersion)`、`generate_summary_cards(goalType,chunkIds)`、`validate_candidate(taskId,resultVersion,sourceVersion)`，三者均拒绝额外字段及不匹配的资料或版本参数。模拟工具仅在本地执行，不调用外部模型和OCR。文字笔记使用原文片段；图片和PDF只使用标题元数据，候选必须显示模拟标识、实际处理页数和“未读取文件正文”提示。

### 10.3 执行与反馈

服务端先载入任务配置和资料快照，拒绝被删除或限制访问的资料。规划器提出下一步工具，执行器校验名称、类型、权限、页段和预算后执行，将结构化反馈加入上下文。文字提取返回无文字页时，可转OCR；OCR无有效文本时，可请求用户重新上传，或以明确的不可解析结果结束。

取得足够片段后生成候选内容，再运行来源与格式校验。允许在预算内根据校验错误修复一次；任务只有在候选结构合格时进入WAIT_CONFIRM。总页数、实际处理页数和质量提示必须写入候选结果并显示。首次接入使用模拟模型验证协议和异常分支，正式AI验收必须切换真实适配器并记录厂商、模型标识、日期和配置。

### 10.4 状态流转

| 状态 | 含义 | 可达后续状态 |
| --- | --- | --- |
| QUEUED | 已提交待领取 | RUNNING CANCELLED |
| RUNNING | worker正在执行 | WAIT_CONFIRM FAILED CANCELLED |
| WAIT_CONFIRM | 候选已校验，等待用户保存 | SUCCEEDED FAILED CANCELLED |
| SUCCEEDED | 用户已确认保存 | 终态 |
| FAILED | 解析失败或输入版本失效 | 终态，可另建重试任务 |
| CANCELLED | 用户取消或资料已删除 | 终态 |

候选生成成功与用户确认完成分别统计，不能把WAIT_CONFIRM计入已完成。待确认期间资料版本变化时，确认接口返回409并把任务标记为FAILED及SOURCE_VERSION_CHANGED。终态任务不复活；重试新建记录并关联父任务。

## 11 异步任务与一致性

### 11.1 领取与租约

worker通过短事务锁定可领取任务，条件更新QUEUED为RUNNING，并递增executionEpoch、写入leaseUntil。建议租约30秒、每10秒心跳一次，外部调用期间由独立定时心跳续约，避免60秒网络调用占满租期。心跳、片段落库、步骤完成和候选结果写入均需校验taskId、当前epoch及RUNNING状态。

过期worker可能仍收到外部响应，因此恢复领取必须递增epoch。旧worker无法更新新执行轮次的数据。数据库事务只覆盖状态更新和本地落库，不在持锁事务内等待OCR或模型网络请求。恢复执行优先复用已完整保存的步骤；状态UNKNOWN的外部调用不能自动宣称未计费。

### 11.2 幂等与取消

提交任务保存请求摘要requestHash，相同幂等键只接受相同输入。确认结果采用任务行锁与resultVersion校验，成功后保存confirmation_json；再次确认时先识别已完成并返回相同结果。卡片唯一键是taskId与candidateKey，作为第二道防线。

取消使用条件状态更新，将cancelFlag置位并转为CANCELLED。worker在每个工具调用前后检查取消和epoch，取消后返回的候选不能持久化为待确认结果。此机制保证后续业务不再落库，不能保证已经发送的API请求一定停止或不会收费。

通知与任务状态在同一短事务内写入，并用dedupeKey约束去重。微信渠道发送在提交后异步处理，失败只修改channelStatus。调用计费的统计基础是ai_tool_call的真实尝试记录，工具缓存命中与本地校验不算实际模型调用。

### 11.3 确认保存事务

保存时依次锁定任务和源资料，校验用户、WAIT_CONFIRM、resultVersion、sourceVersion及访问状态。对来源片段、父卡片和关联目标再做归属与版本检查；将选择的候选转为正式卡片，写来源和所选关系，更新资料摘要及标签、递增版本，保存confirmation_json并转SUCCEEDED。

任何一步失败整体回滚，不出现“任务完成但卡片缺失”或半套来源。用户只选择部分卡片时，包含未选候选卡片的关联必须移除或报字段错误；不能把无效关系默默改为其他目标。

## 12 管理与统计口径

统计采用Asia/Shanghai自然日，查询from包含、to不包含；服务端转换为UTC边界。时间参数必须显式传递，默认最近7天。图表返回日期桶、数据与计算口径，前端不自行计算与后台不一致的任务成功率。

| 指标 | 计算约定 |
| --- | --- |
| 当前有效资料数 | 统计时未删除的资料，包括归档；RESTRICTED单列数量 |
| 上传趋势 | 范围内新建资料数，按创建事件统计，包括随后删除的资料 |
| 热门学科 | 当前有效资料按subject计数，空学科归入未分类 |
| 实际AI调用次数 | 范围内MODEL类工具尝试数，含重试和UNKNOWN，排除本地工具 |
| OCR调用次数 | OCR类实际请求尝试数，与模型调用分开展示 |
| 调用重试次数 | 对同一逻辑步骤attemptNo大于1的外部请求数 |
| 任务状态分布 | 范围内创建任务的当前状态分布 |
| 任务完成率 | SUCCEEDED除以SUCCEEDED加FAILED，分母为0时返回null |
| 候选生成数 | 范围内创建任务中已产生合格候选的数量，单独显示 |
| 费用 | 仅汇总明确提供且币种一致的金额，未知数量单列，不补零 |

取消、排队、执行和待确认不进入任务完成率分母。该口径受用户确认行为影响，因此大屏同时显示待确认数量，论文对比测试另采用任务完成、输出质量和实际成本等指标，不将平台完成率直接当成智能体质量。
