## 四、测试过程中发现的问题

这一轮**没有发现系统功能缺陷**，但暴露了三处工程问题：

### 1. 接口契约文档与代码已经漂移（重要）

冒烟脚本第一版按 `docs/接口契约.yaml` 和常见约定写成，结果 29 项里挂了 12 项，全部是路径或参数猜错：

| 我按约定写的 | 实际实现 |
|---|---|
| `POST /api/auth/sessions` | `POST /api/v1/auth/sessions`（前缀多一层 `v1`） |
| `GET /auth/me` | `GET /users/me` |
| `POST /materials/notes` | `POST /materials`，body 里带 `type: "NOTE"` |
| `PUT /materials/{id}/note` | `PATCH /materials/{id}` |
| `POST /materials/{id}/favorite` | `PUT /favorites/MATERIAL/{id}` |
| `goalType: "CARD_GENERATION"` | 枚举只有 `REVIEW_CARDS / EXTRACT_KEY_POINTS / LINK_NOTES` |
| 统计 `from=2026-10-01` | 必须带 Z 的 UTC ISO8601 + `timezone` 参数 + 上海自然日边界 |

**建议**：引入 springdoc-openapi，启动时生成 `v3/api-docs`，把 `docs/接口契约.yaml` 改成由代码生成、CI 校验的产物，避免文档与实现各说各话。这件事对答辩也有利——可以直接展示 Swagger UI。

### 2. `scripts/verify.mjs` 的 dependencies 阶段被环境拦截

项目自带的验收脚本第一阶段是 `npm --prefix web ci`，本机 npm 装了 safe-delete 保护，删除 50+ 文件时要求交互确认：

```
npm error [safe-delete][SAFE_DELETE_BULK_CONFIRM_REQUIRED] {"count":50,...,"scope":"turn"}
```

脚本随即中止，`releaseReady=false`。这是**环境限制，不是项目缺陷**。本轮改为手动执行等效的三个阶段（node 测试 / mvn verify / vite build），结果与脚本预期一致。

副作用需要说明：`npm ci` 中断时已删除部分包，导致随后 `vue-tsc` 命令找不到。已用 `npm install` 恢复，恢复后前端 304 项测试复跑仍全绿、构建通过。

**建议**：给 `verify.mjs` 增加 `--stage` 参数，允许跳过 dependencies 阶段（依赖已就绪时没必要重装）；或在 CI 里用干净容器规避本机保护钩子。

### 3. 测试数据清理

冒烟脚本创建的笔记与卡片在用例末尾删除（软删除），AI 任务与审核单按业务设计保留留痕。当前开发库状态：
