# D01 后端健康检查与数据库连通：验证记录

日期：2026-10-22。环境：macOS 26.7.1 x86_64，本机独立 MySQL 开发库 `learning_material_dev`。记录不包含数据库凭证。

## 工具与构建

| 工具 | 实测版本 |
| --- | --- |
| JDK | Azul Zulu OpenJDK 21.0.12.1 |
| Maven | 3.9.16，运行于上述 JDK 21 |
| Node.js / npm | 24.22.1 / 11.19.1 |
| MySQL | Community Server 8.0.46 |

`mvn -B -f backend/pom.xml -DskipTests package` 最终返回 `BUILD SUCCESS`，生成 `backend/target/backend-0.1.0-SNAPSHOT.jar`。首次依赖下载在打包阶段遇到本机 SOCKS 代理连接中断；重试后成功，无需修改源码。

## 数据库与启动

1. 独立空库 `learning_material_dev` 可由专用 `lms_dev` 账号通过 `127.0.0.1:3306` 连接，查询到 MySQL `8.0.46`。
2. 用仓库外的本地 `.env` 配置启动后端，Flyway 执行 `V1__create_app_user.sql`。库中出现 `app_user` 与 `flyway_schema_history`；迁移历史为版本 `1`、`create app user`、`success=1`。
3. `GET http://127.0.0.1:8080/actuator/health` 返回 HTTP 200，响应体为 `{"status":"UP"}`，不包含数据库配置。
4. 停止并再次启动后端，健康接口仍返回 HTTP 200；迁移历史仍只有 1 条成功记录，`app_user` 表仍存在。
5. 另建一次性空库 `learning_material_replay_check`，在端口 8081 启动同一构建，健康接口返回 HTTP 200；该库同样产生 1 条成功迁移记录和 `app_user` 表。验证后已停止进程、撤销一次性授权并删除该临时库。

本机 MySQL 的 `lms-mysql-stop` 与 `lms-mysql-start` 也已完成停止、重启和再次连接验证。验证结束后后端进程已停止，主开发库与 MySQL 服务保留。
