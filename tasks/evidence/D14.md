# D14 腾讯云OCR代码与本地验证

日期：2026年10月25日。基线为已包含D12、D13的main（e6bc701）。本次实现腾讯云GeneralBasicOCR适配代码；用户明确选择“先完成代码，密钥稍后配置”。真实腾讯云验收仍未完成，任务清单D14保持待验收。

## 实现范围

- `backend/.../ocr/`：固定HTTPS地址、TC3-HMAC-SHA256签名、凭证前置校验、禁重定向、5秒建连和20秒完整响应超时、2MiB响应上限、字段/置信度校验与固定错误码。默认OCR关闭，只有本地测试可注入loopback端点。
- `OcrImagePreparation`：授权存储读取图片或渲染所选扫描页，分配图像前限制尺寸；JPEG最多1MiB、长边4096、1200万像素。文字层优先，不对未选PDF页面请求OCR。
- `OcrExtractionService`及V9：固定版本页缓存、稳定来源编号和实际页码，单页最多2次、全任务最多20次，跨epoch累计；来源超限不截断。空结果不编造，缺失/低置信度提供质量提示。
- `ocr_attempt`独立记录可能已发出的请求；缓存命中不新增请求。费用未知为NULL；取消、删除、失租或发布失败不接收迟到业务结果。旧执行器的清理限定自己的epoch，防止覆盖新执行器账本。
- 双端候选、确认和正式卡片显示OCR来源及质量；来源删除或受限时隐藏引用、正文和质量说明。摘要和卡片仍明确标注MOCK，外部处理同意文案说明OCR可能向厂商发送图片。
- [本机配置说明](../../docs/OCR接入配置.md)及隐藏输入PowerShell脚本；未写入或提交密钥。

## 本地测试方法

传输测试先观察缺少实现导致的编译失败，再实现并运行本地HTTP服务测试；业务测试先观察无OCR来源、无缓存/账本等失败，再完成实现。后续追加取消、删除、停用、排队文件变化、确认来源及跨epoch竞态回归，均先观察失败再修复。测试用OCR桩只在Spring测试配置中存在，生产代码没有假OCR成功适配器。

后端在独立MySQL开发测试库运行，使用本机环境注入数据库凭证，不连接用户的业务数据库。可复现命令（需本机先配置独立`DB_`测试环境）：

```powershell
mvn -f backend/pom.xml verify
node --test tests/*.test.js
cd web
npm run build
```

传输测试覆盖TC3独立签名向量、实际payload、中英文/置信度、未配置、鉴权错误、限流、空结果、非法置信度、禁重定向、超大响应、延迟响应头及响应体。业务测试覆盖混合PDF范围、20页工具预算、缓存/版本/厂商冲突、空文字、UTF-16分片、有限重试和总尝试预算、原子回滚、权限变化、取消/删除、租约及epoch隔离、确认后来源质量。

## 本地HTTP与页面验证

后端在独立UI数据库启动，显式`OCR_ENABLED=true`、`OCR_PROVIDER=disabled`，确保不调用腾讯云。通过真实登录、上传和任务接口上传自编清晰PNG及纯扫描PDF，任务10、11均返回`FAILED/OCR_NOT_CONFIGURED`。V9迁移成功；数据库核对这两项各有一条FAILED尝试、dispatched=0、cost=NULL，没有OCR页缓存或文字片段。

小程序任务详情逻辑通过真实HTTP读取任务11，显示“尚未配置”提示；Web浏览器实际登录、进入任务详情，显示PDF提取成功、OCR未配置失败及0次可能发送，未同意前不能重试。页面无脚本错误。[页面截图](D14-ocr-not-configured.png)仅验证无配置分支，不代表真实OCR识别效果。原生微信操作仍待验证。

独立传输审查核对[腾讯GeneralBasicOCR文档](https://cloud.tencent.com/document/api/866/33526)及[TC3签名](https://cloud.tencent.com/document/api/213/30654)，未发现阻塞问题。独立规格审查发现旧epoch清理可能误改新epoch请求记录，已增加复现测试，修复为按task_id与execution_epoch清理，并通过只读复核。

本地真实HTTP追加验证发现初版OCR用户状态检查误用ACTIVE，测试造数也沿用同一错误；应用真实注册状态为ENABLED，因此真实账户被错误拒绝。此问题不能以先前单元/集成测试通过为由忽略：回归改为真实AuthService注册用户，先复现失败，再修正guard并重新验证。

独立质量与安全审查完成，未发现其他阻塞问题；针对性复核确认用户状态及真实资料/任务配置契约一致。
