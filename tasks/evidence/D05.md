# D05 笔记编辑与冲突处理：验证记录

日期：2026-10-23。环境：macOS、JDK 21、Node.js 24、MySQL 8。微信开发者工具原生验证按用户此前选择暂缓。

## 已实现

- 后端实现`PATCH /api/v1/materials/{id}`与`DELETE /api/v1/materials/{id}?version=`。更新使用本人ID和`version`条件，成功后版本加1；旧版本返回409及`error.currentVersion`。标题、学科、标签、正文、摘要及使用中/归档状态可按字段更新，标签更新与资料更新在同一事务。删除是逻辑删除，之后详情返回404、列表不再展示正文。
- Web加入编辑页、归档/恢复/删除和状态筛选。编辑页离开时提示未保存内容，并把草稿保存在当前标签页的`sessionStorage`中；冲突后保留草稿，展示服务器版本，只有用户明确确认才用服务器版本替换。
- 小程序加入编辑页、归档/恢复/删除和状态筛选。输入时将草稿保存在本机，冲突时展示服务器版本并保留草稿，保存成功才清除。删除前有确认提示。
- 当前还没有异步任务表和worker；资料删除后取消非终态任务的设计将在D09至D10实现。

## 验证结果

1. 隔离空库`learning_material_auth_test`运行`mvn -B -f backend/pom.xml test`：Flyway V1至V3迁移成功，3项集成测试通过，0失败、0错误。两客户端同时提交版本1时，恰好一次200、一次409；409返回当前版本2，最终标题、正文和标签保持同一获胜编辑。旧版本归档和删除均409；归档后默认列表隐藏、归档列表显示；删除后详情404、全部列表不可见；其他账号修改及删除返回404。测试库及授权已删除。
2. `cd web && npm run build`通过，包含Vue类型检查。`node --test tests/*.test.js`共10项通过，其中新增3项覆盖小程序编辑冲突保留草稿、成功后清草稿、归档与删除传递当前版本。
3. 小程序页面JSON解析通过，`git diff --check`通过。接口契约补充了409响应的`currentVersion`字段。
